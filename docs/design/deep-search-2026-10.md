# 深掘り検索（意味検索の結果を、出典リンクつきで新しいノートにまとめる）

状態: 設計と実装中（2026-10-02）。利用者の依頼: 「検索結果を deep search するボタンを付けたい。意味検索で引っかかった文書の前後の文字を、それぞれの検索結果ファイルから抽出して LLM に投げ、参照リンクつきで新しいノートに出力する」。方針は、`search-summary-prep-2026-10.md`（準備）と、利用者が承認した提案（下の §1）。

## 1. 承認された方針

| 項目 | 決め |
|---|---|
| 前後の取り方 | 「前後 N 文字」ではなく**項目**（`---` や見出しの 1 件）単位。項目全体を最大 1,500 文字。それより長い項目は、ヒットした行の前後約 700 文字。短い項目（300 文字未満）は、前後の項目を、それぞれ最大 400 文字まで足す。同じ項目に当たった複数のヒットは 1 つにまとめる |
| 件数 | 既定 10 件（検索パネルの既定と同じ）。ボタンからは最大 30 件。送る文字数の合計は約 18,000 文字まで |
| 引用 | LLM に URL を書かせない。出典に番号を付けて渡し、答えの `[n]` は、アプリが「存在する出典の番号だけ」に絞り（ない番号は落とす）、出典の一覧（ファイルへのリンクつき）を答えの下に付ける。本文の `[n]` を長い `file:///…` のリンクにしない（エディタで読む生のテキストが、ほぼ住所だけになる。プレビューは `file:` のリンクを描かない）。**引用した原文の抜粋**（`> 原文 [n]`）が、その出典の本文に含まれるかを照合し、含まれなければ「(未検証)」を付ける |
| 出力先 | **新しいタブ（未保存のノート）**。保存先は利用者が決める。スクラップフォルダに保存しても、深掘りのノートは索引に入らない（先頭の目印 `<!-- md-memo:deepsearch -->`） |
| 送る前 | 「N 件・約 M 文字・送り先（このパソコン／クラウドのホスト）・除いた秘密の数」を確認ダイアログに出す。クラウドは、ホストごとの同意（既存の `general.cloudConsent`）が要る |
| 実行 | 背景タスク（タスクパネルに出る、取り消せる） |
| モデル | 設定の `text` モデル（質問バーと同じ） |
| 除外 | `.md-memo-ignore`、隠しフォルダ、assets、同期の競合コピー、AI の結果ブロック、深掘りのノート。秘密（API キー、トークン、秘密鍵、`password=` など）は伏せ字にする |
| スコア | 数字や「一致度 %」は見せない（順位だけ） |

## 2. 流れと Go 側の部品

```
検索パネル（意味モード）の結果 ──[深掘り]──▶ DeepSearchPlan ──▶ 確認ダイアログ ──[実行]──▶ DeepSearchRun ──▶ 新しいタブ
                                            （意味検索 → 抜粋 → 除外・秘密除去）           （プロンプト → LLM → 引用の置換と照合）
```

- `pkg/deepsearch`: `BuildSources`（抜粋、除外、予算、秘密除去）、`BuildPrompt`、`Resolve`（`[n]` を存在する番号だけに、原文の照合）、`Compose`（ノートを組み立てる）。純粋な関数で、ファイルを読む以外の副作用はない。
- `app_deepsearch.go`: プランの保存（15 分、最大 8 件）、LLM の呼び出し、取り消し、同意の確認（Go 側でも、同意のないクラウドへは送らない）。
- Ollama は、既定の文脈長（約 4,000 トークン）で、長いプロンプトの先頭（指示）を黙って切り捨てる。**ローカルの Ollama には、`num_ctx` をプロンプトの大きさに合わせて渡す**（`llm.Config.NumCtx`）。

## 3. 画面とバックエンドの契約（`window.backend`、すべて Promise）

### 3.1 検索パネルの意味モード

`config.semantic.enabled` が true のとき、検索パネル（Ctrl+Shift+F）に「完全一致 | 意味」の切り替えを出す。意味モードでは、入力が止まって約 400 ms で検索する（埋め込みの呼び出しがあるため、完全一致より遅くしてよい）。

`window.backend.searchScrapsSemantic(query, limit)` → 次の形（`limit` は 10 から始め、「さらに表示」で 30）:

```jsonc
{
  "semantic": true,          // false: 意味検索はできず、単語の検索に切り替わった（notes に理由）
  "pending": 0,              // 索引にまだない（新しい、変更された）ファイルの数
  "truncated": false,        // limit より多くあった
  "notes": ["..."],          // 画面に 1 行で出す（足切りの数、単語検索への切り替え、未索引など）。英語の文
  "results": [               // 既存の searchScraps と同じ形（キーは camelCase。ファイルごとにまとめる）
    { "fileName": "2026-09-01.md", "filePath": "C:\...\2026-09-01.md",
      "matches": [ { "lineNumber": 3, "lineText": "...", "snippet": "", "heading": "2026-09-01 09:00", "headingLine": 0,
                     "endLine": 3, "score": 0.58, "source": "semantic" } ] }   // endLine と source は意味検索で足した項目。score は数字として見せない
  ]
}
```

エラー（機能がオフ、同意のないクラウド、モデル未設定）は、Promise の reject（`Error.message` が文）。画面は、その文を 1 行で出し、完全一致のモードに戻す導線（切り替え）を残す。

### 3.2 深掘り

`window.backend.deepSearchPlan(query, limit)` → 検索して、抜粋を作り、**LLM にはまだ送らない**:

```jsonc
{
  "plan_id": "p_1727870000_1",
  "query": "...",
  "model_configured": true,         // false: text モデルが未設定（質問バーと同じセットアップの案内を出す）
  "semantic": true,                 // false: 単語の検索に切り替わった（notes に理由）。それでも深掘りはできる
  "notes": ["..."],
  "sources": [                      // 送る出典（番号順）
    { "n": 1, "label": "2026-09-01 09:00", "date": "2026-09-01", "rel": "2026-09-01.md",
      "chars": 812, "start_line": 3, "end_line": 9 }
  ],
  "stats": { "used": 10, "ignored": 1, "ai": 0, "unreadable": 0, "budget": 0, "total_chars": 9120, "masked": 2 },
  "est_tokens": 6100,               // 送る内容の大きさの見積り（日本語は約 1.5 文字、英語は約 4 文字で 1 トークン）
  "destination": {
    "model": "bge...", "host": "api.openai.com", "local": false,   // local: このパソコンの中（loopback）
    "consent_key": "api.openai.com",                                // 同意の保存先のキー（https はホスト、http は "http://ホスト"）
    "consent_given": false                                          // local のときは常に true
  }
}
```

`window.backend.deepSearchRun(planId, lang)`（`lang` は画面の言語 `ja` か `en`）→ LLM に送り、答えを組み立てる:

```jsonc
{ "title": "深掘り 竹の話",          // タブの名前（.md は付けない）
  "markdown": "<!-- md-memo:deepsearch -->\n# ...",
  "stats": { "sources": 10, "cited": 6, "unverified": 1, "verified": 4, "invalid_refs": 0, "model": "..." } }
```

エラーは reject（`Error.message`）。画面が分岐する符号は次のとおりで、ほかは文（1 行で出す）:

| `message` | 起きる場所 | 画面の動き |
|---|---|---|
| `cancelled` | run | 取り消された。何も出さない（タスクは「取り消し」に） |
| `consent_required` | run | 同意のないクラウドへは送らなかった。確認ダイアログで同意を取ってやり直す。**同意は `rememberCloudConsent` のあと `await savePersistentConfig()` で config.json に書き終えてから run を呼ぶ**（Go 側は config.json を読んで確かめる） |
| `model_not_configured` | run | text モデルが未設定（plan の `model_configured: false` のときは、画面が先に案内を出す） |
| `plan_expired` | run | プランは 15 分で消える、または一度実行すると消える。plan からやり直す |
| `superseded` | searchScrapsSemantic | 新しい検索に置き換えられた。**黙って捨てる**（文を出さない） |

件数が 0 件のとき、`deepSearchPlan` は `plan_id: ""`、`sources: []` を返す（エラーではない。画面は「該当するノートがありません」を出す）。同意の保存先は、text モデルのホスト（`destination.consent_key`）で、このパソコンの外（ローカルネットワークの別の機械を含む）は同意が要る（質問バーより厳しい）。

`window.backend.cancelDeepSearch(planId)` → 実行中なら、結果を捨てる（LLM への要求そのものは止められない）。

## 4. 確認ダイアログ（画面の仕様）

- 内容: 「N 件のノート（約 M 文字）を、`<モデル>`（このパソコン／`<ホスト>`＝クラウド）に送り、出典リンクつきでまとめます」。出典の一覧（日付・見出し・文字数。折りたたみ可）。「除いたもの」（除外、AI の結果、秘密 K 件を伏せ字にした）。単語の検索に切り替わっていれば、その旨。
- クラウドで `consent_given` が false: 同意の文と「許可して実行」。許可は、既存の同意（`rememberCloudConsent(consent_key)`）に保存する。ローカルは、同意の文を出さない。
- 実行: 背景タスク（`TaskManager`、種類 `deepsearch`、取り消しは `cancelDeepSearch(plan_id)`）。完了したら、**新しいタブ**に `markdown` を入れて選び、「深掘りの結果を新しいノートに出力しました」を出す（検索パネルは閉じる）。
- 取り消し、失敗: 何も作らない（失敗は 1 行のメッセージ）。
- 誤操作: ダイアログを出した直後（約 350 ms）の Enter は無視（既存の同意と同じ）。既定のフォーカスは、キャンセル。
- 絵文字は使わない。アイコンは、アプリ統一の線画 SVG。文言は、日本語と英語の両方（`i18n.js`）。

## 5. 出力のノート

```markdown
<!-- md-memo:deepsearch -->
# 深掘り: 竹の話

（答え。事実を書いた文の最後に、出典の番号 [1] [2]。番号は下の「出典」の行に対応する）

## 根拠
> 竹は成長が早く、3年ほどで伐採できる。 [1]
> （原文にない抜粋には「(未検証)」が付く）

## 出典
1. [2026-09-01 09:00](file:///…/2026-09-01.md) — 3〜9 行目
2. [2026-09-02 10:00](file:///…/2026-09-02.md) — 5〜7 行目（本文では使われていません）

---
作成: 2026-10-02 22:10 ・ モデル: gemma4:e2b ・ 意味検索 10 件（足切り 0.85）・ 送った出典 10 件、約 9,100 文字 ・ 秘密 2 件を伏せ字
```

リンクは、エディタの `[label](target)` の形（`file_anchor.js`）で、ファイルを開く（行は指せないので、行は文で併記する）。ラベルに `]` を含めない（エディタの正規表現が壊れる）。

## 6. 評価（合成データ）

`tools/semindex-eval` で、質問 → 抜粋 → 答え → 引用の照合まで、LLM を差し替えて確かめる（引用の番号の誤り、存在しない番号、原文にない抜粋を、確実に検出できること）。実際のモデルでの品質は、利用者のノートでの確認が要る。
