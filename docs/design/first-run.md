# 初回起動: ようこそノートと、AI の一度きりの選択（2026-09-30）

対象: [ux-review-2026-09.md](ux-review-2026-09.md) の **A1**（初回体験がない）と、**A2 のうち初回の選択画面**（D2 の事前確認）。ステータスバーの「AI: 未設定」表示（A2 の残り）と、質問バーの送り先の行（I3）は別担当で、ここでは触れない。

実装は新しいモジュール `frontend/js/first_run.js`（判定と文面だけの純粋関数）と、`app.js` の小さな呼び出し数か所。`index.html` で `app.js` より前に読み込む。モジュールが無い状態（古いテストの模擬環境など）では、何も起きず、今までどおり動く。

## A1: ようこそノート

新規インストールの最初の起動だけ、日付見出しだけの空ノートの代わりに、編集できる「ようこそ」ノート（タブ名 `Welcome` / `ようこそ`）を1つ出す。中身は、書き方、`Ctrl+L` で AI に聞く（初回は選択画面が出る、設定 > AIモデル で変えられる）、`Ctrl+Shift+P` のパレット、`Ctrl+,` の設定、`Ctrl+Shift+F` の日付ノート検索、ノートの保存先。ショートカット名は、その PC で有効なもの（Mac は Cmd、割り当てを変えていればその表記）を入れる。UI の言語（`general.language`）で日本語か英語。

### 「初回」の判定

すべてが同時に成り立つときだけ。

| 条件 | 見るもの |
|---|---|
| 設定ファイル（`config.json`）が無い | バックエンドの `GetConfig()` が空文字を返した。**答えが分からないとき（バックエンドが無い、読み込みに失敗）は初回として扱わない** |
| `general.welcomeShown` が無い | メモリ上の設定 |
| ブラウザ側の設定コピーが無い | `localStorage` の `md_notepad_config_v3` / `md_memo_config_v1` |
| 保存されたセッションが無い | `localStorage` のセッション、バックエンドの `session.json` |
| 覚えているワークスペースフォルダが無い | `localStorage` の `md_memo_workspace_folder` |
| 起動時に渡されたファイルが無い | `GetStartupFile()`（ダブルクリック、Open with、コマンドラインのパス） |
| 最初のノートに手が付いていない | タブが1つ、ファイルなし、未保存の変更なし、中身が空か日付見出しだけ（エディタの現在の値で判断） |

更新した人（以前の版を使っていた人）には必ず `config.json` があるので、この表の1行目で出ない。`config.json` が無いことが、決定的な条件になる。

### なぜバックエンドの答えを待つか

最初の描画は、今までどおり `localStorage` から同期で行う（日付見出しのノートが1つ出る）。「初回か」の決め手は `config.json` の有無で、それはバックエンドにしか分からない。そこで、`syncBackendConfig()` が設定を読み終えた直後（`getSession` と設定の同期のあと）に判定し、まだ手が付いていない最初のノートを、その場で「ようこそ」に差し替える。判定は起動の途中で待たない。差し替えまでの数ミリ秒は空のノートが見える（初回だけ）。

- 逆にしない理由: `localStorage` が空なだけで先に「ようこそ」を出すと、WebView のプロファイルが消えた既存ユーザーに一瞬出て、あとで消すことになる。
- 差し替え前にその人が打ち始めていたら、何もしない（打った文字は消さない）。この場合 `welcomeShown` も書かない。次の起動ではセッションがあるので出ない。

### 書き込むもの

`{"general":{"welcomeShown":true,"toolbarLayout":{…}}}` だけを `config.json` に書く。全設定を書かない理由: 言語（OS の言語から決まる既定）や IME ガーディアンの既定（`nativeImeSwitch` が無い OS では OFF にする判定）を、その日の値のまま設定ファイルに固めてしまうのを避ける。あとで設定を保存すれば、いつもどおり全体が書かれる（そのとき `welcomeShown` も入る）。Go 側の読み取りは、欠けた項目を既定値で扱うので、部分的な `config.json` で困らない（`parseScrapConfig` など）。

書いたあとは `config.json` が存在するので、`welcomeShown` が何かの拍子に消えても、ようこそノートは二度と自動では出ない。

**ツールバーの配置を一緒に書く（A5 との取り合い）**: 設定が何も保存されていない新規プロファイルは、落ち着いたツールバー（アイコン7個、`calmToolbarLayout`）で始まる。ただしそれは「設定ファイルが無い」ことが条件で、設定ファイルがあって配置が無いと「すべて表示」と読まれる（`applyCalmToolbarForNewProfile`、`hasSavedConfig`）。フラグだけを書くと、2回目の起動でツールバーが全アイコンに変わってしまう（模擬環境で、フラグのみ = 隠すアイコン 0 個、フラグ + 配置 = 10 個と確認）。そこで、そのとき有効な `general.toolbarLayout` をフラグと一緒に書く。同じ理由で、設定のブラウザ側コピー（`localStorage`）は書かない（あると「使い込んだプロファイル」と読まれる）。ほかに「設定ファイルが無いこと」を初回の条件にしている既定を追加するときも、同じ扱いが要る。

### セッション復元との関係

- 「ようこそ」のタブは、ふつうの未保存ノート（ファイルなし、変更なし）としてセッションに保存される。**開いたまま終了すると、次の起動でも他のタブと同じく復元される**（勝手に消さない）。閉じれば戻らない。自動で新しく開く処理は、上の判定で二度と通らない。
- セッションがある起動、設定ファイルがある起動では、この処理は最初の条件（`configFileFound !== false`）で終わる。起動時の追加コストは真偽値の判定1つ。

### 新しい空のタブの日付見出しは**残す**（決定）

レビューの直し方は「日付見出しをバッファに入れず、プレースホルダーが出るようにする」だったが、変えない。

- **見出しに依存しているもの**（`grep` で確認）: `note_title.js`（無題ノートの名前。見出し以外に何も無いときの名前、保存名 `YYYY-MM-DD_<要約>.md` の日付は見出しから取る）、`app.js` の起動ファイル置換の判定（`content.startsWith('# ')`）、`tests/rpc_write_tabs_test.mjs` / `tests/hot_path_parity_test.mjs` / `frontend/js/note_title_test.js`、マニュアルの「無題ノートの名前の付き方」。`md-memo tab new` も同じ `createTab` を通る。
- 見出しを外すと、タブ名が `untitled-N.md` から始まり、保存名の日付の由来も変わる。全ユーザーの毎日の動作が変わるのに、得られるのは「空のノートに薄いヒントが出る」だけ。
- 初回の問題（何も案内がない）は、ようこそノートで解く。2枚目以降の新規ノートのヒントは、日付見出しを残したままでは出せない。必要なら別の形（空のノートの一行目に薄い案内を重ねるなど）で検討する（未着手）。

## A2: 質問バーの一度きりの選択

条件: 質問バー（`Ctrl+L`）または書き換えバー（`Ctrl+K`）を開いたとき、`general.aiChoiceMade` が無く、テキストモデルが**手の付いていない既定**（`http://localhost:11434`、`qwen2.5:latest`、キーなし）で、モデルが答えられる状態（未設定のバナーが出ない）。

出るもの: 質問バーの中、対象のチップの下に、既存のバナー（`.inline-prompt-setup`）と同じ作りの帯（`#inline-prompt-choice`）。警告ではないので、琥珀色ではなく中立の色。ダイアログではなく、入力欄のカーソルもそのまま。

| ボタン | 種類 | 動作 |
|---|---|---|
| ローカルモデル（Ollama）を設定 / Set up a local model (Ollama) | 主（塗り） | 選択を記録して質問バーを閉じ、設定 > AIモデル を開いて「ローカルAI」のカードを見せ、インストールのボタンにフォーカス |
| クラウドのキーを使う / Use a cloud key | 副（枠線） | 記録して、設定 > AIモデル の Text LLM の欄（URL、モデル名、APIキー）を見せ、APIキーの欄にフォーカス。折りたたまれた節は開く |
| あとで / Later | 三次（薄い塗り） | 記録して帯を閉じる。バーは開いたまま |

- 記録は `general.aiChoiceMade = true` を `config.json` に保存（全設定の保存）。設定を開く前に保存するので、設定の「キャンセル」で巻き戻らない。
- 3つのどれかのほか、**既定のモデルのままバーを実行した（Enter / Run）ときも記録する**（Ollama が動いている人には、これが答え）。Esc で閉じただけでは記録しない。
- 失敗の帯（D1）とは同時に出さない。失敗が出るのは実行のあとで、実行した時点で記録済み。念のため失敗の帯を出すときに選択の帯を隠す。
- 既存ユーザーで、テキストモデルを既定のまま使っている人にも1回だけ出る（`aiChoiceMade` が無いため）。ほとんどは「あとで」か、そのまま実行すれば済む。

## 残り・引き継ぎ

- **設定パッケージ**: `welcomeShown` と `aiChoiceMade` はこの PC の状態なので、`general.cloudConsent` と同じく `config_pack.js` の `LOCAL_ONLY_NESTED` に足して、書き出しにも取り込みにも通さないのが筋（別担当のファイルなので手を付けていない）。今のままだと、取り込みでこの2つが上書きされうる（影響は「ようこそ」が出ない / 選択画面が出ない、のどちらか）。
- **起動ファイルの経路（既存の不具合、今回は直していない）**: 起動時にファイルを渡され、最初のタブが手つかずの日付見出しだけのとき、`initApp` は `tabs[0].content = startupFile.content` のあとに `selectTab` を呼ぶ。`selectTab` は先に「今のエディタの値」を離れるタブへ書き戻すので、内容が日付見出しに戻り、タブ名とパスだけがファイルのものになる（Edge + モックで確認。実機の WebView2 では未確認）。そのまま打つと自動保存で元のファイルが上書きされうる。直し方は、ようこそノートと同じく、`selectTab` の前に `editorEl.value` を新しい内容にしておく。
- 2枚目以降の空のノートに出す薄いヒント（上の「決定」の続き）。
- 「ようこそ」をもう一度開くパレットの項目（閉じたあとに読み返したい人向け）。
