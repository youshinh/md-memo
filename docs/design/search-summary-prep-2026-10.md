# 検索結果をリンク付きで要約する機能への準備（2026-10-02）

状態: 機能そのものは未着手（利用者の依頼: 「後で、ファイル検索結果の内容をリンク付きで要約（まとめる）機能を追加したい。その点を配慮してほしい」）。ここは、後で足すときに作り直しが要らないように、今の実装で用意したものと、決めておくことの記録。

## 1. 今、用意してあるもの

| 必要なもの | 用意したもの |
|---|---|
| 検索結果の各ヒットを、リンクとして引用する材料 | 全種類の検索（通常、`ranked`、`semantic`、単語検索への切り替え）の各ヒットに `rel`（スクラップフォルダ内の相対パス、`/` 区切り）、`url`（`file://` の URL。エディタの `pathToFileUrl` と同じく、各区間をパーセントエンコード。空白、括弧、角括弧を含まないので、Markdown のリンクを壊さない）、`label`（日付と直近の見出し）、`link`（`[label](url)`、そのまま貼れる）。`pkg/cli/links.go`。CLI の JSON と RPC の `scrap.search` の両方 |
| 引用の位置 | `line`、`end_line`（意味検索）、`heading`、`date` は、これまでどおり。リンクはファイルを開くだけで行を指せないので、行は別の項目として併記する |
| 要約の材料（本文） | 意味検索は `context`（その項目全体、既定 1,200 文字まで）と `text`（最も近いチャンク）。単語検索は一致した 1 行（`text`）だけ（§2） |
| 要約の書き込み先 | 開いているノート（`buffer.append`、`buffer.select` + `buffer.replace_selection`）、今日のスクラップ（`scrap.append` の `format: "markdown"`。**囲み（```text）なしで書くので、中のリンクがクリックできる**）、新しいタブ（`tab.new` の `content`）、結果を開く（`scrap.open`） |
| 検索の窓口 | RPC `scrap.search`、`ui.open_panel` の `scraps_search`（検索パネルを開く）。意味検索（実験）も同じ引数 |
| 名前の固定 | 上の項目の名前と意味は、後方互換にする（要約の機能が依存する） |

## 2. 後で決めること（未決）

1. **行を指すリンク**。エディタのリンクは、ファイルを開くだけ（`file_anchor.js`、`OpenPath`）。行まで飛ぶには、`file:///…/2026-09-01.md#L12`（GitHub と同じ形）を読んで、その行へ移動する処理が要る。足すか、行は「(L12)」と併記するだけにするか。足すなら、ヒットの `url` に `#L<line>` を付ければよい（`url` 自体は変えない）。
2. **単語検索のヒットの抜粋**。要約には、一致した 1 行だけでは足りない。案: (a) `ranked` のヒットにも `context`（その項目全体、上限つき）を足す。(b) `scrap.read {rel, line?, end_line?}`（スクラップフォルダの中だけ、読み取り専用）を足す。要約を作る処理が使うので、実装するときにどちらか（または両方）を選ぶ。
3. **要約を作るモデルと同意**。要約には LLM が要る（利用者の設定の `text` モデル、またはクラウド）。ノートの内容を送るので、質問バーと同じ規則（送り先の表示、クラウドは、ホストごとの `cloudConsent`）にする。意味検索の埋め込みの同意（`semantic.privacy.cloudConsent`）とは別。
4. **引用の作り方（捏造を防ぐ）**。モデルには、番号つきの出典（`[1] label — 本文`）だけを渡し、出力の `[n]` を、アプリが、ヒット n の `link` に置き換える。**モデルに URL を書かせない**。出典にない番号は取り除く。
5. **送る範囲**。単語検索は `.md-memo-ignore` を見ていない（意味検索の索引は見る）。要約に送る前に、除外の規則（`.md-memo-ignore`、AI の結果ブロック、秘密に見える文字列の除去 `pkg/llm/redact.go`）を、ヒットに適用する。
6. **量の上限**。出典の件数 × 1 件の文字数（トークンの予算）。多いときは、分けて要約してから、まとめる。
7. **別の PC でも壊れないリンク**。Git で同期するスクラップフォルダは、PC ごとに絶対パスが違う。要約を、スクラップフォルダの中のノートに書くときは、そのノートからの相対リンク（`./2026-09-01.md`、サブフォルダなら `../`）にする。`rel` を返すのは、このため。フォルダの外のノートや、他へ貼るときは、絶対の `url`。
8. **入口**。GUI（検索パネルの「要約」、コマンドパレット）、CLI（`scrap summarize <text> [--semantic] [--into ...]`）、RPC（`scrap.summarize`）。**RPC からモデルを呼ぶのは、AI を起動するメソッドを足さない方針（`rpc-additions-2026-10.md` §4）との整合を、そのとき判断する**（呼ぶモデルは、利用者が設定したもの。費用と送信が出る）。
9. **結果の置き方**。既存の AI の結果ブロック（`<!-- md-memo:res -->`、確認、取り消し、コピー）に載せるか。載せるなら、ブロックの中でリンクがクリックできるかを確認する（今は未確認）。

## 3. この機能が使う順序（想定）

検索（`scrap.search`、意味検索を含む）→ ヒットから出典の一覧を作る（件数、文字数、除外の規則）→ モデルに要約させる（番号つき）→ `[n]` を `link` に置き換える → 開いているノート、または、`scrap.append`（`format: "markdown"`）で書く。
