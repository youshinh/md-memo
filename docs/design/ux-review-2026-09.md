# UX レビュー 2026-09-29: 初めて触る人にとってのとっつきやすさと、コーポレート品質への課題

依頼: 「設定画面の説明が多い。初心者向けにアドバンスは折りたたむ。とにかく初めて触る人にはとっつきにくい。コーポレートレベルのプロダクトにするため、見た目・操作・操作動線をレビューしてほしい」。

## 方法と限界

- 実際の `frontend/` を、モックのバックエンド（`tools/docshots`）と隔離した Edge で動かし、実際のキー入力・マウス入力（CDP）で触って調べた。日本語は文字列の走査だけ。
- 幅 1120x720 を基準に、800x600・600x500・1600x900 も確認した。コントラストは、実際の計算後の色から WCAG の比を出し、4つのテーマすべてで測った。
- **確認できていないこと**: 本物の Ollama や Gemini の挙動（モックのみ）、OS 標準のツールチップ、ウィンドウの枠、macOS、スクリーンリーダー、クイックキャプチャ（モックでは非表示）。
- 指摘は調査担当のエージェントの出力。**コードで裏を取ったもの**は「確認済み」と書いた（A1、D1、D3、F1、I2）。ほかはスクリーンショットと測定値を根拠にしているが、私は再現していない。スクリーンショットは調査時のスクラッチ領域にあり、リポジトリには入れていない。

## 上位の課題（初めて触る人がつまずく順）

1. **初回体験がない（A1）**。新規インストールで見えるのは、`# 2026-09-18 10:24` という見出しだけのノートと、ラベルのないアイコン15個、状態表示6個。ヒントになるプレースホルダーは、新規ノートに日付見出しが入るため、そもそも出ない。
2. **主役の AI が最初の `Ctrl+L` で失敗する（A2、D2）**。既定は、ふつうの人が持っていないローカル Ollama。それでも状態表示は「Predict: ON」「Action: ON」と言い、モデルの設定へ案内する場所がない。
3. **AI の失敗が、ノートの本文に書き込まれる（D1、確認済み）**。生の Go のエラー文（日本語混じり）が `[LLM error: ...]` としてそのまま入り、再試行も設定を開く操作もない。
4. **「AI が未設定」が行き止まり（D3）**。`Ctrl+L` で何も開かず、12px のトーストが途中で切れる。選択範囲はそのままなので、次に打つ文字が選択を上書きしてしまう。
5. **見つけにくさと専門用語（A3、A4、H1、I1）**。コマンドパレットに「設定」「保存」「検索」「ヘルプ」がない。ヘルプは外部サイトだけ。バージョンやライセンスを見る画面がない。Scraps、slot、Degram Engine、Predict、Action といった内部用語が UI に出る。
6. **全体に効く P1**: 主要ボタンの文字のコントラストが 2.1〜3.7:1（F1）。フォーカスの輪郭が約 1.3:1（F4）。ARIA がほぼなく、ダイアログにフォーカストラップがない（G1、G2）。タブが5枚を超えると「+」が画面外に出る（B2）。AI の進行表示が出ているまさにその間、ヘッダーとステータスバーが 12〜15% の濃さまで薄くなる（B8）。
