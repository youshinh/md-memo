# 探索的テスト計画（2026 Q4）

依頼: 探索的テストの本から得た視点（名詞×動詞、ライフサイクルの追跡、内部理解と What If、Checking の安定化、AI とのペアテスト）を使って、MD-Memo の品質を上げるテスト計画を組む。

この計画は**まだ一度も実行していない**。人数・時間の見積もりは推定で、最初の 2 セッションのあとに見直す。記録用のひな形は [templates.md](templates.md)。

## 1. 考え方

- **Checking（確認）と Exploring（探索）を分ける。** 決まった答えのある確認は自動テストに寄せ、人と AI の時間は「答えが分からないところを探す」ことに使う。
- **探索でバグを見つけられても、なぜ気づけたかを言葉にする。** 見つけたバグ 1 件ごとに「気づきの型」を 1 つ付け、あとで型ごとに数える。これが「手順を体系化できていない」感覚への答えになる。
- **探索で見つけたものは自動テストに還流する。** 直したバグには、可能なら回帰テストを付ける。付けられないもの（見た目、OS 依存）は理由を記録する。
- **探索中は直さない。** バグ候補を記録するだけで進む。修正は別の時間にまとめてやる（文脈の脱線を防ぐ）。

## 3. 探索の視点をこの製品に当てる

### 3.1 名詞 × 動詞

MD-Memo の名詞と動詞を並べ、**普段やらない組み合わせ**を意図して作る。

名詞: ノート（タブ）/ 選択範囲 / キャレット / アンカー（`[AI Generating…]`）/ 結果ブロック / タスク（`{{ }}`、`[[ ]]`）/ パネル（質問・書き換え・コマンド・提案・検索・パレット）/ 分割ペイン / プレビュー / スクラップ（日付ノート）/ 設定（config.json）/ agents.yaml / クリップボード / 画像 / 音声 / ウィンドウ / ホットキー

動詞: 作る / 開く / 貼る / ドラッグする / 選ぶ / 分割する / 取り消す（Ctrl+Z、Esc）/ やり直す / キャンセルする / 閉じる / 保存する（自動を含む）/ 復元する / 書き出す・取り込む / 名前を変える / 切り替える / 変換中に押す（IME）/ 最小化・リサイズ / 終了して再起動する

### 3.2 ライフサイクルの追跡

「作った」で終わらず、時間軸と状態遷移を最後まで追う。次の 6 つを、それぞれ端から端まで通す。

| 対象 | 遷移 | 落とし穴になりやすい所 |
|---|---|---|
| AI の要求 | 入力 → アンカー挿入 → 待ち → 成功 / 失敗 / キャンセル / タイムアウト → ノートの状態 → 元に戻す | 遅れて届く答え、二重の答え、行き先のタブがない、Ctrl+Z の段数 |
| ノート | 新規 → 編集 → 自動保存 → タブの復元 → 名前を付けて保存 → 外部で変更 → 閉じる → 再起動 | 強制終了、外部での削除・変更、読み取り専用、文字コード |
| 設定 | 既定 → 編集 → 保存（差分保存）→ 書き出し → 取り込み → 版をまたぐ → 既定に戻す | 途中で閉じる、未知のキー、言語の切り替え中、詳細表示の記憶 |
| タスク・結果ブロック | 記述 → 実行 → 進捗 → 結果ブロック → 元に戻す（Esc）→ 再実行 → 編集 | 分割ペイン、キャンセル、巨大な出力、書式の壊れた目印 |
| Mobile Drop / スクラップ | QR 表示 → 接続 → 受信 → ノートへ挿入 → 期限切れ / 日付が変わる → 同期 | ネットワークの切り替え、複数の端末、Git の衝突 |
| アプリ | 起動 → 常駐 → ホットキー → 終了 → 更新確認 → アップデート後の初回起動 | 2 つ目の起動、クラッシュ後、DPI・複数モニター、macOS の Gatekeeper |

### 3.3 内部理解と What If

開発者の目で全体像を持ち、「もしこうなったら？」を意図して作る。このアプリの内部から出てくる問い:

- **プロセスと OS**: WebView2 の呼び出しは UI スレッドで同期に走る → 重い呼び出しの最中に別の操作が来たら？ ネイティブのダイアログの持ち主（owner）がなくなったら？ 単一インスタンスの mutex を持ったまま落ちたら？
- **データ**: 自動保存は 1.5 秒の待ち → その間にタブを閉じる・強制終了したら？ 目印（アンカー、`<!-- md-memo:res -->`）を利用者が手で消したら、コピーしたら？ 目印が入ったまま別のノートに貼ったら？
- **通信と AI**: モデルが答えを返さない・2 回返す・途中で切る・巨大な答えを返す・`<think>` だけを返す・コードフェンスで包む → それぞれのとき、ノートは？
- **時間**: 時計が戻る・進む、0 時をまたぐ、スリープから復帰する。タイマー（フェード、自動保存、更新確認、ゴースト予測）が重なるとき？
- **入力**: IME の変換中、合成中のキー、Option 合成（macOS）、貼り付けの種類（HTML、Word、Excel、画像、ファイル）、ドラッグの種類。
- **環境**: Ollama が起動していない・途中で止まる。`claude` などのエージェントが PATH にない。パスに空白・日本語・短縮名。オフライン。ディスクがいっぱい。
- **設定**: 古い版の config.json、未知のキー、手で壊した YAML、ショートカットの衝突。
- **見た目と入力の同時変化**: フェード中に再度開く、フォーカスが戻る、ウィンドウが小さい、ズーム、ダークだけのテーマでの読みやすさ。

## 4. Checking を安定させる（探索の前に終わらせる）

探索に時間を使えるように、確認の部分を先に固める。新しく足すものは次のとおり（優先順）。

1. **操作の列を機械に作らせる（ファジング）**: 既存の質問バー用の模擬環境（`tests/ask_and_command_bar_test.mjs` の `createEnv`）の上で、「質問・取り消し・失敗・タブ切り替え・閉じる・Ctrl+Z」をランダムな順で（種を固定して）実行し、**不変条件**を確かめる: 「すべての要求が決着したら、ノートに `[AI Generating` が残らない」「文字が理由なく消えない」「保留中の要求の数が 0 に戻る」。名詞×動詞を機械にやらせる形。工数: M。
2. **主要な流れのスモークテスト**（`tests/smoke_*.mjs`、画像なし）: docshots の基盤（隔離 Edge＋CDP＋モック）で、新規ノート → 書く → 質問 → 結果 → 保存 → 検索 → 設定を開いて閉じる、を 10〜12 本、DOM と状態だけで合否判定する。Windows の CI に入れる。工数: M。**実装済み（CI への組み込みはまだ）**: `tests/smoke/` に 12 本、`node tests/smoke/run.mjs`（探索キットの上、既定で 3 本並列、約 20 秒。`--lang ja` で日本語 UI、`--only`、`--jobs`、`--shots`）。`tools/run_js_tests.mjs` には入れていない。既知の不具合は、その確認だけを既知の問題として印付けしてある（D5 の Ctrl+Z など）。
3. **リリース前のチェックリスト化**: docshots の全撮り直し → 画像の目視（今回のリリースでやったこと）、GIF の撮り直し、`go test`、JS 全件、CI の緑、成果物のハッシュ照合、を 1 枚にする。工数: S。
4. **障害注入のフック**: docshots のハーネスに「AI が失敗する・遅れる・二重に返す」「保存が失敗する」を切り替える口を用意する（`ask-bar-error` の撮影ですでに 1 つ使った方法を一般化）。探索でも自動テストでも使う。工数: S〜M。
5. **既知の空白**: 副作用を出さないテストの方針のため、実ウィンドウの動作は自動化しない。macOS の実機は探索で確かめる。

## 5. AI（Claude Code）とのペアテスト

| 役割 | 誰 | 仕事 |
|---|---|---|
| ナビゲーター | あなた | 憲章（何を探るか）を決める。問いと方針を出す。見た目や使い心地の判定、重大度の判定 |
| ドライバー兼記録係 | Claude Code | 操作する。観察したことを逐次ログに書く。証拠（画像、状態のダンプ、ログ）を保存する。バグ候補を起票用の形に整える |

**Claude が使う道具**（安全な順）:
1. 隔離した Edge＋モックのバックエンド（docshots の基盤）: 本物のフロントを、実データに触れずに動かす。AI の答えと失敗を台本で入れられる。**既定はこれ。**
2. JS の模擬環境（`createEnv`）: 状態機械の細部を、速く大量に試す。
3. 稼働中の実アプリ（`md-memo-cli` のフルパス版）: **あなたの許可があるときだけ**。書き込みは最小限にし、保存確認のダイアログが出る操作（タブを閉じる）は避ける。config.json の書き換えはしない。

**進め方**（1 セッション 45〜90 分、1 憲章）:
1. 憲章を読み上げて、範囲と「やらないこと」を決める。
2. Claude が環境を用意し、操作を 1 つずつ実行して「操作 → 観察 → 疑問」を書く。あなたは疑問に答え、次の一手を指す。
3. 変だと思ったら、その場で**バグ候補**として書く。このとき「気づきの型」と「なぜ気づけたか」の 1 行を必ず付ける。
4. 探索中は直さない。原因の仮説は書いてよい。
5. 終わりに 5 分の振り返り: 学んだこと、次の憲章、自動テストにできるもの。

**気づきの型**（タグ）: `NV` 名詞×動詞 / `LC` ライフサイクル / `WI` What If / `OR` オラクルの不一致（マニュアル・他の画面・前の版・期待と違う）/ `RC` タイミング・並行 / `ENV` 環境

**Claude が得意なこと・苦手なこと**: 得意 — 大量の組み合わせを黙々と試す、記録を欠かさない、証拠を残す、起票用に整える。苦手・やってはいけない — 見た目の良し悪しや使い心地の判定を単独で下す、重大度を決める、macOS や実機のことを推測で断定する、許可なく実アプリを操作する、見つけたその場で直してしまう。

## 6. 優先順位（リスク）

| 順 | 領域 | 理由 |
|---|---|---|
| P0 | データを失わない（自動保存、復元、アンカー、元に戻す、AI 失敗時） | 一度でも起きると信頼を失う。過去にアンカー周りの不具合が複数あった |
| P0 | 固まらない（巨大ノート、貼り付け、同期呼び出し） | 過去に 8 万行で固まった |
| P1 | 初回体験（未設定の AI、Ollama がない、最初の Ctrl+L） | レビューで最重要と指摘された |
| P1 | プライバシーと安全（データの行き先、API キー、エージェントのガード、Mobile Drop） | 企業導入で見られる |
| P1 | macOS 実機（Finder、⌘、Gatekeeper、WKWebView の差） | 未確認の点が残っている（スイッチ、`:has()`、ターミナル起動、スロットが実行中で止まる） |
| P2 | アクセシビリティ（キーボードだけ、フォーカス、読み上げ） | 第 1 弾で入れたが、通しで見ていない |
| P2 | 言語（日英の全画面、日付・数の書式、文字の漏れ） | 過去に漏れが多かった |

## 7. 憲章（最初の 14 本）

書式: 「〈対象〉を、〈資源・方法〉で探り、〈知りたいこと〉を見つける」。優先度は §6 に対応。

| ID | 優先 | 憲章 | 使う視点 | 主な What If |
|---|---|---|---|---|
| C1 | P0 | AI 要求の一生を、取り消し・失敗・並行・タブ操作で探り、ノートが壊れる経路を見つける | LC, NV, RC | 答えが遅れて 2 回来る、行き先のタブがない、Ctrl+Z の段数、失敗表示の残り |
| C2 | P0 | ノートの一生を、自動保存・強制終了・外部変更・読み取り専用で探り、内容を失う経路を見つける | LC, WI | 1.5 秒の待ち中に終了、外部で削除、ディスクいっぱい |
| C3 | P0 | パネル 6 種を、選択・フォーカス・IME・Alt+Tab で探り、入力が消える・意図と違う範囲に効く経路を見つける | NV, RC | 入力ありでフォーカスが外れる、変換中に開く、選択が途中で変わる |
| C4 | P0 | 巨大・異常な入力（8 万行、1 行 10 MB、混在改行、絵文字、巨大貼り付け）で、固まる・崩れる機能を見つける | WI | ゴースト、分割、プレビュー、検索、行番号の同時使用 |
| C5 | P1 | 分割ペイン・プレビュー・タスクの組み合わせで、結果の行き先と強調のずれを見つける | NV, RC | 片方を閉じる、同じノートを両側で編集 |
| C6 | P1 | 設定の一生（差分保存、書き出し・取り込み、版をまたぐ、言語切り替え）で、値が消える・戻る経路を見つける | LC, WI | 古い config、未知のキー、開いたまま言語を変える |
| C7 | P1 | エージェント・コマンドの実行を、失敗・巨大な出力・存在しない・長時間で探り、ノートとタスクパネルの食い違いを見つける | LC, ENV | PATH にない、空白・日本語のパス、閉じる前に確認 |
| C8 | P1 | クリップボードと画像（HTML、Word、Excel、画像、ファイル）の貼り付け・ドラッグで、変換の崩れと待ちの混線を見つける | NV, WI | 巨大な HTML、OCR 未設定、続けて貼る |

| C10 | P1 | プライバシーと安全（データの行き先、キーの扱い、エージェントのガード、ファイルリンク）で、意図せず外に出る・実行される経路を見つける | WI, OR | 書き出しにキーが入る、ガードの回避、パスの組み立て |
| C11 | P1 | 起動・常駐・終了（単一インスタンス、トレイ、ホットキー、更新確認）で、二重起動・取り残し・遅い起動を見つける | LC, ENV | クラッシュ後の再起動、ホットキーの衝突、オフライン |

## 8. 4 週間の進め方

|---|---|---|

## 9. 指標と、やめる条件

- **見つけた数**: セッションあたりのバグ候補（重大度別）。
- **気づきの型の内訳**: `NV` / `LC` / `WI` / `OR` / `RC` / `ENV` の件数。多い型は、憲章と自動テストの重点にする。
- **還流率**: 修正したバグのうち、回帰テストが付いた割合（付けなかったものは理由つき）。
- **見逃し**: リリース後に見つかった不具合の数（憲章のどこにも入っていなかったもの）。
- **記録にかかった時間**: 探索時間の 10% 以下を目標。超えたらテンプレートを削る。
- **やめる・見直す条件**: 3 セッション続けてバグ候補が 0 件なら、その領域は自動テストに任せて憲章を入れ替える。逆に 1 セッションで P0 が出たら、同じ領域の憲章を追加する。

## 10. やらないこと

- 実際のクラウド AI にあなたの API キーで大量に問い合わせること（同意があるときだけ、少量）。
- あなたの本物の config.json・agents.yaml・ノートを書き換えること。
- 許可なく、稼働中の MD-Memo を操作すること。
- 探索中にその場でバグを直すこと。

## 11. 確認できていない前提

- 見積もり（工数 S/M、1 セッション 45〜90 分）は推定。
- 「過去の不具合の傾向」は、記憶に残っている記録から挙げたもので、課題管理の全件ではない。
- macOS 実機と実 WebView2 の窓での挙動は、この計画の C12 と、あなたの環境でのセッションで初めて確かめられる。
