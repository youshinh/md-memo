### C11-15 （キット）`s.state()` は 5 MB を超えるノートがあるとページとの通信が止まり、以後の `s.ev` も返らない

- 重大度（案）: P3（探索の道具の問題。アプリの不具合ではない）

- 期待（オラクル）: 大きな値でも返る、または時間切れで診断が出る

### C11-16 （キット）Ctrl+N / Ctrl+T / Ctrl+W / Ctrl+Shift+N は実キーでページに届かない。起動時の障害を入れる口がない

- 重大度（案）: P3（探索の道具の問題）
- 気づきの型: ENV
- なぜ気づけたか: `s.key('n', {ctrl:true})` で新しいタブが増えない。ページの keydown を見ると何も来ていなかった（Ctrl+S / D / L / Alt+D は来る）。C2-12 は Ctrl+W でページが閉じたと報告している
- 再現手順: 監視を付けて `s.key('n', { ctrl: true })`
- 期待（オラクル）: アプリの ショートカットを試せる（実アプリの WebView2 ではブラウザの予約キーは無効）
- 実際: 届かない。回避は合成の `KeyboardEvent`（このセッションで使用）。もう 1 つ、README の `backend`（起動時に適用）は実際は「起動後」に効くので、`getSession`・`getStartupFile`・`getConfig` の起動時の障害や、大きなセッションを渡せない。私は 2 回目の読み込みで補った（`scripts/lib.mjs`）
- 環境: 版 1.10.5 · キット `tools/explore` · headless Edge · Windows 11
- 再現性: 毎回（2 回中 2 回）
- 証拠: EV `scripts/pq.mjs` `pq2.mjs` `lib.mjs`
- 原因の仮説: `tools/explore/kit.mjs` の `startExplore` の `init` に `session`・`faults` を足し、`page_hooks.js` の `transformBoot` で反映する。予約キーは合成イベントにフォールバックする `s.key`
- 自動テストにできるか: できる（キー変換は既存の純粋関数のテストに、フォールバックは追加）

## 気づきの型の内訳

NV: 2 件（C11-02、C11-05）/ LC: 1 件（C11-03）/ WI: 5 件（C11-06、C11-07、C11-09、C11-10、C11-12）/ OR: 3 件（C11-04、C11-08、C11-14）/ RC: 3 件（C11-01、C11-11、C11-13）/ ENV: 2 件（C11-15、C11-16）

重複: C11-01 = C2-03、C11-05 = C2-07、C11-07 = C2-11、C11-16 の Ctrl+W = C2-12。独立の再現なので、件数の集計ではナビゲーターが統合を判断する。

## 振り返り（5 分）

- 学んだこと（次に同じ型で探すときのヒント）: 「起動の分岐（`return` で抜ける経路）と、その後ろの仕事」を読むと当たりが多かった（C11-03、C11-14）。「同じ意味を持つ別の入口」（Ctrl+W、✕、RPC、起動ファイル、常駐中の「開く」）を並べ、片方だけ検証や後始末が抜けていないかを見るのが効く。ダイアログは「開いている間に来る別のキー」を必ず試す（C11-01、C11-02）。更新確認、About、オフ・オフライン・失敗の表示は設計どおりで平易だった（C9 と一致）
- 次にやる憲章: 実 WebView2 での起動ファイル付き起動と、常駐中の 2 つ目の起動（C11 の実機版、あなたの環境）。セッションが上限を超える大きなノート（5 MB 超）を持つ利用者での、終了 → 再起動 → 保存のライフサイクル（C4 と C2 の交点）
- 自動テストにできるもの: (1) セッション復元のファジング（不正な要素、重複 id、`content` なし、切れた JSON）を `restoreSessionFromData` に。不変条件: 起動が完走し、正常な要素だけが残る。(2) `confirmSaveDialog` の再入と修飾キー（DOM の模擬環境）。(3) 起動ファイル付きの `initApp` が `getSession` を読み、更新確認を予約すること。(4) 「開く」の全入口が `findTabByPath` を通ること
- うまくいかなかったこと（道具・進め方）: キットに起動時の障害を入れる口がなく、2 回目の読み込みの補助が要った。`s.state()` が巨大なノートで止まり、9 分を失った（CDP の大きな値には時間切れが要る）。ほかの探索セッションが 6 本以上並行して動いていて、起動時間は上限の目安（実機や空いた機械ではもっと速い）。ブラウザの予約キーで Ctrl+N / W が届かない
