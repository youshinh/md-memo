- 期待（オラクル）: "theqq" には一致がないので何も開かない（待つ）
- 実際: 古い一覧の先頭 2026-09-17.md が開いた（クエリ欄は `theqq` のまま）
- 環境: `a8bfea5` / キット / en
- 再現性: 毎回（2/2）
- 証拠: `s13.mjs`、`s14.mjs`
- 原因の仮説: 入力時に `scrapsSearchFlattened` を空にするのは空クエリの時だけ（app.js 8220-8225）
- 自動テストにできるか: できる

### C3-20 パレットの定型プロンプトは「入力あり」と数えられず、ノートをクリックすると消える

- 重大度（案）: P3 ― 定型文なので失うものは小さい
- 気づきの型: OR
- なぜ気づけたか: `panel_fade` の `dirty` が input イベントでしか立たないのに、パレットは `value` を直接代入する
- 再現手順: 選択 → Ctrl+Shift+P →「polish」または「bullet」→ Enter（定型文がバーに入る）→ ノートをクリック
- 期待（オラクル）: 入力のあるバーは閉じない（panel-template）
- 実際: 0.6〜0.9 秒後にバーが閉じ、定型文が消える
- 環境: `a8bfea5` / キット / en

- 証拠: `s10.mjs`、`s14.mjs`

### C3-21 （キット）Ctrl+W をキット経由で送るとページが閉じ、以降の呼び出しが返らない

- 重大度（案）: P3 ― キットの制約。探索の妨げ
- 気づきの型: ENV
- なぜ気づけたか: 確認ダイアログの検証で `s.state()` が返らなくなった
- 再現手順: `s.key('w', {ctrl:true})` のあとに `s.ev('1+1')` / `s.state()`
- 期待（オラクル）: アプリの Ctrl+W ハンドラが動く（タブを閉じる / 確認ダイアログ）。README の「ブラウザにはショートカットが届かない」記述
- 実際: ノート（ダーティ・クリーンとも）で、以降のすべての CDP 呼び出しが応答しない（タイムアウトもない）。ブラウザのタブを閉じるアクセラレータが効いた可能性が高い
- 環境: `tools/explore/kit.mjs`（headless=new の Edge）
- 再現性: 毎回（3/3）
- 証拠: `s20.mjs`〜`s22.mjs`
- 原因の仮説: `Input.dispatchKeyEvent` の rawKeyDown がブラウザのアクセラレータになる。`page.eval` にタイムアウトがなく、ページが消えても待ち続ける
- 自動テストにできるか: できる（キットの単体テストで `keyEvents` を検査、または `s.ev` に既定のタイムアウトを付ける）

## 気づきの型の内訳

NV: 8 件（C3-01, 05, 06, 07, 09, 13, 15, 16）/ LC: 0 件 / WI: 0 件 / OR: 6 件（C3-02, 08, 10, 14, 17, 20）/ RC: 6 件（C3-03, 04, 11, 12, 18, 19）/ ENV: 1 件（C3-21。C3-10 も環境依存の注記つき）

（各候補に主となる型を 1 つ付けた集計、計 21 件。LC と WI は今回の憲章ではほとんど使わなかった：状態の一生や内部の What If より、パネルどうしの組み合わせと時間差で見つかった。）

## 不具合なし（確認できたこと）

- 変換中（`imeSetComposition`）に Ctrl+L / Ctrl+K を押しても、変換は確定して残り、文字は消えない。バーは開く（計画 #7 を満たす）。
- 質問バー・コマンドバー・ノート検索は、変換中の Enter を無視する。
- フェード: 入力なし → 0.4 秒 + 0.2 秒で閉じる／フォーカスが戻れば残る／入力あり・エラー表示中・クラウド同意の質問中は残る。Alt+Tab 模擬（ウィンドウ非アクティブ）では閉じず、戻ってからフォーカスが外にあれば閉じる。設計どおり。
- 待ち中に別タブへ移って AI が失敗する場合は、バーではなくトーストが出る（計画 #3 のとおり）。
- 検索バー + 質問バーは重ならない（質問バーは下端に出る）。

## 振り返り（5 分）

- 学んだこと（次に同じ型で探すときのヒント）:
  1. 「開いた時に固定する状態」と「実行時に読み直す状態」の食い違いは、バーごとに別の実装になっている（質問 = 固定、コマンド = 実行時、検索 = 検索時）。同じ問い「間にノート編集・タブ切り替え・ペイン切り替えを挟む」を全パネルに当てると、ほぼ全部に当たった。
  2. 入力欄の Esc / Enter は「入力欄で処理 → ウィンドウで処理」の二重処理になる。`stopPropagation` の有無を機械的に洗える。
  3. 非同期の結果（提案パネル・コマンドバー）は、タブ ID を持たない経路が残っている。AI 要求だけが安全に作られている。
  4. IME は合成イベントで形を仮定した。実機（Windows WebView2 / Mac）でイベントの形を採取してから重大度を決めるとよい。
- 次にやる憲章: C5（分割ペイン × 結果の行き先。C3-03/04/06 が同じ根）、C13（キーボードだけ・モーダルとフォーカス。C3-09 が入口）。IME の実機採取（Mac）を C12 に足す。
- 自動テストにできるもの: ファジング（`ai_lifecycle_fuzz_test.mjs`）に「バーを開いた後のノート編集」「選択が改行で終わる」「タブ切り替え」の操作を追加。`panel_fade` / `jev_action` / 検索置換 / パレットの `action` を模擬 DOM で試す単体テスト（C3-05, 07, 10, 12, 18, 19, 20）。
