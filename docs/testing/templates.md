# 探索的テストのひな形

[exploratory-test-plan.md](exploratory-test-plan.md) で使う、セッションの記録とバグ候補の書き方。セッションの記録は `docs/testing/sessions/YYYY-MM-DD-cNN-題.md` に置く（なければ作る）。

## セッションの記録

```markdown
# セッション YYYY-MM-DD: C?? 〈憲章の題〉

- 憲章: 〈対象〉を、〈資源・方法〉で探り、〈知りたいこと〉を見つける
- 時間: 開始 hh:mm / 終了 hh:mm（計 分）
- ナビゲーター: 〈名前〉 / ドライバー兼記録係: Claude Code 〈モデル〉
- 環境: 版 x.y.z（コミット 〈sha〉）/ OS / 道具（ハーネス · 模擬環境 · 実アプリ）
- 範囲外（やらないこと）:

## ログ（時系列）

| 時刻 | 操作 | 観察 | 疑問 · 次の一手 |
|---|---|---|---|
| hh:mm | 例: Ctrl+L → 「短くして」→ Enter → すぐタブを閉じる | 例: タスクパネルに「失敗」が残る | 例: 遅れて届く答えはどこへ？ |

## バグ候補

（下の「バグ候補」の形で。ID は B-YYYYMMDD-連番）

## 気づきの型の内訳

NV: 件 / LC: 件 / WI: 件 / OR: 件 / RC: 件 / ENV: 件

## 振り返り（5 分）

- 学んだこと（次に同じ型で探すときのヒント）:
- 次にやる憲章:
- 自動テストにできるもの:
- うまくいかなかったこと（道具・進め方）:
```

## バグ候補

```markdown
### B-YYYYMMDD-01 〈一行の題〉

- 重大度（案）: P0 / P1 / P2 / P3 ― 決めるのはナビゲーター。Claude は根拠だけ書く
- 気づきの型: NV / LC / WI / OR / RC / ENV
- なぜ気づけたか: 〈1 行。どの組み合わせ・どの遷移・どの問いから〉
- 再現手順:
  1.
  2.
- 期待（オラクル）: 〈何と比べて変か: マニュアル · 他の画面 · 前の版 · 目的 · 常識〉
- 実際:
- 環境: 版 · OS · 道具（ハーネス · 模擬環境 · 実アプリ）· 言語
- 再現性: 毎回 / 時々（回中 回）/ 一度だけ
- 証拠: 画像 · 状態のダンプ · ログの場所
- 原因の仮説（任意）:
- 自動テストにできるか: できる（どこに）/ できない（理由）
```

## 重大度の目安

| 重大度 | 目安 |
|---|---|
| P0 | データを失う、固まる、勝手に外へ送る・実行する、起動できない |
| P1 | 主要な操作が進めない、壊れて見える、回避策が分かりにくい |
| P2 | 仕上げ、見た目、まれな組み合わせ、回避策がある |
| P3 | あればよい |

## 気づきの型のカタログ（4 週間で育てる）

| 型 | 意味 | 例（実際にあったもの） |
|---|---|---|
| NV | 名詞×動詞の、普段やらない組み合わせ | 複数の AI 結果 × あとから届く結果の挿入 |
| LC | ライフサイクルを最後まで追った | 保存の待ち中に閉じたら？ |
| WI | 内部を知っているから出た「もし」 | 同期呼び出しの最中に別の操作が来たら |
| OR | 何かと食い違っている | 別のパネルと幅が違う、マニュアルと動作が違う |
| RC | タイミング・並行 | 並列に動かして初めて出た、強調が先の結果で消える |
| ENV | 環境の差 | 短縮名の一時フォルダ、Mac、オフライン |

新しく見つかった型は、ここに足す。
