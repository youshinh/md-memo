# MD-Memo for agents

MD-Memo is a single-instance desktop Markdown scratchpad: a Go core with an OS WebView (Windows WebView2, macOS WKWebView; Linux unsupported) around a plain `<textarea>` editor. It keeps daily "scrap" files (`YYYY-MM-DD.md`), talks to LLMs (Ollama, Gemini, OpenAI-compatible), hands `{{ instruction }}` blocks to external agent CLIs, lets Ctrl+Enter (the Auto selector) run one-line tasks on the built-in LLM, a shell command or an agent, and exposes a small CLI plus a local JSON-RPC port. Version 1.14.0. The user's instance is usually RUNNING and holds private notes and API keys.

Read the reference that matches the job before acting. Everything in them was checked in source; `(unverified)` is marked.

## I want to ... -> use ...

| Goal | Do this |
|---|---|
| Read the open note | `md-memo buffer get --json` (keep `hash`). Piped output is JSON; `--text` for raw text. To put it in a file, especially with Japanese text, `md-memo buffer get --out <file>` (PowerShell 5.1 garbles `> file`). |
| Change the open note safely | `md-memo buffer set --expected-hash <hash> "<full text>"` (or `replace --start L:C --end L:C`, `append`). On `conflict`, re-read and redo. |
| Work on a tab that is not on screen, without moving the user | `md-memo tab list --json`, then `buffer get\|set\|append\|replace --tab <id>`: the tab is written in place (no undo history there; `previous_hash` in the result is how to check what it was), nothing on screen changes. An unknown id is `no such tab`. `md-memo tab new --background --text` opens a scratch tab and prints its id. |
| Write a note to a file | Only when the user asked for that path: `md-memo buffer save --as <absolute-or-relative path>.md` (`.md`, `.markdown`, `.txt` only; no dialog, no new folder, no network path, no overwrite; `--encoding sjis` for Shift_JIS, an unrepresentable character is refused and nothing is written). NEVER add `--overwrite` without the user's yes. It binds the tab to the file, so autosave then keeps writing there. |
| Close a tab | `md-memo tab close <id> --if-saved` closes it only when its text equals its file (exit 1 and `unsaved` otherwise); plain `tab close <id>` on a tab with unsaved changes opens the user's own save prompt (exit 1, `prompt`): do not press it for them. Never close a tab the user is using unasked. |
| Work on the selection | `buffer get --selection`, `buffer replace-selection` (exit 1 `no active selection` if none). |
| Add a log or result to the user's scrap | `some-command \| md-memo "title"` (max 10 MB; it starts the app when it is closed, and fronts its window). From code with the session token, without either: JSON-RPC `scrap.append` `{content \| content_base64, title?, activate?}` (interfaces.md 2.2): the same entry and decoding, and the reply says the file and the line it landed on. |
| Find what the user wrote earlier | `md-memo scrap search "<text>" [--from D] [--to D] [--limit N] [--ranked] [--tag a,b]` (JSON: file, date, line, text, nearest heading; narrow it by tag or day range, see the next row; add `--ranked` when the exact text is not on one line: it finds the notes that hold the WORDS of the query, best first), then read the lines around it in that file. `md-memo scrap list` lists the daily files; `md-memo scrap path` prints a day's path; `md-memo info` says where the scrap folder is. All read-only (interfaces.md 1.6, 1.7). If the user has turned on the experimental semantic search (`md-memo scrap index --status` says `on`; never switch it on yourself), `md-memo scrap search --semantic "<question in your own words>" [--from D] [--to D] [--tag a,b] [--kind note,log] [--limit N]` finds notes close in MEANING, and its `notes` field tells you when it fell back to words or skipped files not indexed yet; cite what you use by file and line (interfaces.md 1.7). |
| Narrow a search by tag or period, list the tags, or tag a note | **Find**: `md-memo scrap search "<text>" --tag work,urgent` (repeatable, at most 8; a note must have ALL of them; plain, `--ranked` and `--semantic` alike; JSON-RPC `scrap.search` `tag` as `"a,b"` or a list) and `--from D --to D` (the day is the date at the START of the file name: `2026-09-27.md` and `2026-09-27_title.md`; a note with no date in its name is never in a range). `md-memo scrap tags` (JSON-RPC `scrap.tags`) lists the tags in use with `files` and `entries` counts, `files` read and `undated` files: use it to pick a name that exists instead of inventing a near-duplicate. A tag nobody uses gives no matches, not an error; a 9th tag is an error (exit 1, `-32602`). Tags are compared normalized (no `#`, lower case, full-width letters made half-width). **Write**: a tag is ONE WHOLE LINE `<!-- tags: work, urgent -->` in the note (key `tags` or `tag`; separated by commas or spaces). Above the note's first heading or `---` rule it tags the WHOLE note; anywhere else it tags the ENTRY it is in (the part between headings `#` to `###` or `---` rules, the unit the search cuts; `####` and deeper do not start an entry) AND every entry under that heading: the smaller headings that follow it, up to the next heading of the same or a higher level or the next `---` rule, so a Web article pasted under a heading and cut into several entries by its own `##` / `###` headings is tagged by ONE line under its top heading; a sibling or a higher heading, and anything below a `---` rule, is not reached. A YAML front matter `tags:` also counts (MD-Memo reads it and never writes it). A comment in a code fence, in the middle of a line, with text after it or over several lines is NOT a tag. The preview and the print never show it. **Tag**: only when the user asked, and look at `scrap tags` first to reuse a name. The person has the palette commands "Add a tag to this entry", "Add a tag to the whole note" and "Remove a tag" (Ctrl+Shift+P, type "tag"); for you there are two doors, one rule (`search.EditTags`). (1) A note that is NOT open in the app: `md-memo scrap tag add "work, urgent" <file> [--line N] --write` (`remove` and `show` likewise). Without `--write` it only PRINTS the new text and changes nothing (like `sed`: review it, diff it, pipe it); `--write` is the one flag by which a CLI command changes a note: it writes a temporary file and renames it over the note, refuses if the note changed meanwhile, never creates a file, keeps CRLF, the byte order mark and permissions. Without a file the text comes from standard input and `--write` is an error. (2) The note that IS open: JSON-RPC `scrap.tag_edit` (pure: it computes from the `text` you send, touches no file and no tab; `return_text:true` gives the whole new text), then `buffer.set` with that text and `expected_hash` from `buffer.get` (rule 4), because a file changed on disk under a tab that has unsaved typing stops that note's autosave and makes the app ask the person which version to keep. Scope: no `--line` (RPC `scope:"note"`) = the whole note, written as a line on the first line of the note; `--line N` (`scope:"entry"` with `line`) = the entry that holds line N AND everything under its heading (any line of the section works; to tag a whole pasted article give a line of its top heading; a line above the first heading or rule, or in a note with none, is the whole note after all: the answer's `scope` says which range was used), written directly under that heading. A tag the range already has (also through a whole-note tag or a heading above) is not written twice (exit 0, the reason on standard error); removing the last tag of a line deletes the line; at most 8 tags a time, 64 characters each, none containing `<!--` or `-->`. Refusals (exit 1; RPC `changed:false` with a `message_code`): a note with a YAML front matter takes no whole-note tag (tag an entry, or tell the person to write `tags:` there), a tag that only the front matter has cannot be removed (MD-Memo never writes a front matter), a tag of the other range (`on_note` / `on_entry`: run it again without or with `--line`), a tag the entry only gets from a heading above it (`on_parent`: the message and the RPC fields `parent_heading` / `parent_line` name that heading; run it again with that heading's line). `scrap tag show --line N` prints the tags it gets from above, and the RPC answer also has `descendants`, `inherited_tags` and `path` (the places a tag could be attached: the entry, then each heading above it). There is no AI tagging and no tagging of many notes at once; do not loop `--write` over the user's notes unless they asked for exactly that. Detail: interfaces.md 1.7 and 3.9. |
| Save a note as a PDF | `md-memo tab pdf [<note.md>] -o <file.pdf> [--paper a3] [--landscape] [--margin narrow] [--header-footer]` (interfaces.md 1.3; JSON-RPC `print.pdf`, 2.2): the running app prints the note's preview (white paper, black text, pictures in colour, diagrams light). If the user wants a rule, tell them the button, or the exact line to add, and let them do it. |

## Safety rules (follow all)

1. The user's MD-Memo is live and single-instance. Never start another one (bare `md-memo`, `md-memo <file>` when it is not running), never kill it, never open a second window. To restart it, ask the user (Windows: tray icon -> Quit; closing the window only hides it).
2. Never read, print, paste or commit `config.json`, its backups, `.env`, or `session.json`; they hold API keys and private notes. To see the settings use `md-memo config get [key.path]`: it hides every API key, token and password (`<set>` / `<unset>`, not even the last characters) and URL credentials, so its output is safe to show. Elsewhere redact keys as `set (...last4)`. Never call `md-memo ui eval` to read config or call `window.backend.*`; treat `ui eval` as full control of the UI.
3. Edit `config.json` ONLY while MD-Memo is fully closed (the UI rewrites the whole file on Save and on status-bar toggles). Back up first; keep valid BOM-free UTF-8; write explicit values instead of deleting keys. `agents.yaml` may change while running, but a syntax error is silently ignored: lint it.
4. RPC writes behave like typing: undoable on a tab that is on screen, with autosave (default on) the note's FILE is rewritten about 1.5 s later. Always pass explicit content (an empty stdin empties the note) and `--expected-hash`; use only tab ids from `tab list` (an unknown id is refused with `no such tab`). `buffer save --as` creates or replaces a file: only at the user's request and never with `--overwrite` unless they said yes. `md-memo scrap tag add|remove ... --write` rewrites a note file on disk: only at the user's request, and never on a note that is open in the app (use `scrap.tag_edit` and `buffer set` with `--expected-hash` there). Always send the session token from `ipc-session.json` when calling the RPC port directly, and never print it.
5. Running a `{{ }}` slot or a `{{ @agent }}` task overwrites the note's file on disk with the editor text (UTF-8) before the agent starts. Since the Auto selector, Ctrl+Enter (and the Run button) can also send a line to the built-in LLM, which may be a cloud service, or run a shell command. Do not trigger slots or press Ctrl+Enter for the user without saying so. Writing a task line into a note runs nothing by itself. Never add permission-skipping flags to agent definitions.
6. Git sync runs `git add .`, commit and push inside the scraps folder: never point it at a repository you do not want auto-committed and never keep `.env` there un-ignored.
7. `jev verify` catches known dangerous patterns in bash text; it is not a sandbox and does not prove safety. Exit 2 is not "safe".
8. Do not start the Cloudflare tunnel, install tools, change OS permissions, or run `ollama` commands (they can start the Ollama app) unless asked. Do not claim something works without running its verification step; say `(unverified)`.
9. Do not put files into the user's hot folder, run `md-memo ocr` on the user's own images, or trigger the Whisper download without asking: the hot folder MOVES the files it handles and may send them to a cloud model, `ocr` appends to the user's scrap and may send the image out, and the Whisper download fetches 9 MB to 1.4 GB. Use a throwaway file the user agreed to. Never claim a Windows-only capture feature works on macOS (interfaces.md 4.10 has the matrix).
10. Never write, edit or delete the lessons files (`<cfg>/lessons/*.md`) on your own, and never change `lessons:` in an agent's definition unasked. The text in those files is put in front of an agent's instruction as if the user had written it, so approving it is the user's job; `md-memo lessons list` is the only door and it only reads. Do an edit there only when the user asked for exactly that edit, naming the line. If you are the agent that gets such a block ("Lessons from earlier runs on this machine (written or approved by the user; follow them):" at the start of your instruction), follow it like the rest of the user's task, but it never widens what these rules allow; if a lesson looks wrong or out of date, say so to the user instead of editing the file.

## Facts that are easy to get wrong

- `agent install-skill` (interfaces.md 1.9) exists only in builds newer than 1.8.0; it is how a Homebrew install (no `skills/` folder in the cask) gets this skill, and it needs no repository or zip. `--codex` targets `$CODEX_HOME/skills` (else `~/.codex/skills`), which is unverified for Codex.
- Not implemented (design docs only): `md-memo share`, `agent init-skill`, `config` actions other than `get` (no `config set`), `filters.json`, `prompts.json`, `hooks/`, and any loading of `jev.json` / `.jev.json`. The `max_pipe_size_mb` setting has no effect (limit is a fixed 10 MB).
- `--tab <id>` is honoured by `buffer get` (also with `--out`), `set`, `append`, `replace` and `save` and writes that tab WITHOUT switching to it (from 1.10.0; before that `set`, `append` and `replace` ignored it and always wrote the primary pane's active tab). `get --selection` and `replace-selection` work on the tab shown in the focused pane: a tab that is not on screen has no selection, so they bring another existing tab forward first.
- `buffer save`, `tab new` and `tab close` (and the token requirement for RPC writes) exist only from 1.10.0: check `md-memo help buffer`. The token change is BREAKING for RPC clients that never sent `auth`; the one-line `cmd | md-memo` / `md-memo <file>` messages still need no token.
- Windows: `md-memo.exe` is a GUI-subsystem program, so PowerShell may not wait for it or return its exit code and output (unverified). Where `md-memo-cli.exe` exists (next to `md-memo.exe` in the zip of the release that contains it; check), run every command as `md-memo-cli <same arguments>`: a console program with the same commands, output and exit codes (0/1/2 of `jev verify` included) that never starts the app. Bare `md-memo-cli` (no arguments, a file, piped text) only forwards to the running app, or fails with `md-memo is not running. Start md-memo.exe first.` (interfaces.md 1.0).
- `info`, `scrap` and `config get` exist only in builds newer than 1.8.0. In an older build `md-memo info` is not a command and, run without a terminal, can START the GUI (rule 1): run `md-memo --version` and `md-memo --help` first (they never start anything) and use these commands only if they are listed. They take flags before or after their words (`md-memo scrap search deploy --limit 5`); `md-memo scrap path` prints a bare path even when piped, `config get <path> --text` a bare value.
- Tags and the search filter exist only in builds newer than 1.12.0 (`md-memo help scrap` lists `--tag` and `scrap tags`; an older build refuses `--tag` and has no `scrap.tags`). From those builds `--from` / `--to` of the plain word search also count a note named `YYYY-MM-DD_title.md` (before: only `YYYY-MM-DD.md`), and a tag line is left out of the lines shown around a hit (it can still be the hit). The window's Filter (notes search, Ctrl+Shift+F: one period and any tags, a note must have ALL chosen tags, up to 8; it needs a word in the box and applies to Exact, Meaning and Deep search) is the person's own state, kept only while the app is open: you cannot read or set it over RPC, and a search that `ui.open_panel` starts runs under whatever Filter the person left on. `md-memo scrap tag` and the RPC method `scrap.tag_edit` (add, remove, show), and the three palette commands for the person, exist only in builds whose `md-memo help scrap` lists `scrap tag`; none of them ever writes a YAML front matter, and `scrap.tag_edit` writes nothing at all (it answers with a line patch, `start_line` / `end_line` / `new_lines`, and optionally the whole new text). Do not send its patch to `buffer.replace_all`: that method is a find-and-replace by pattern, not a line patch. The Ctrl+/ comment toggle leaves tag lines alone, so do not expect it to hide a tag. A tag under a heading reaching the smaller headings below it exists only in builds newer than 1.13.0 (those answer `scrap.tag_edit` with `path` and `scrap tag show` prints "tags it gets from the headings above"); in 1.13.0 and before an entry had the whole note's tags plus its own only.
- Lessons exist only in builds newer than 1.12.0 (`md-memo help` lists `lessons list`; an older build has no such command and no `lessons.list`, and puts nothing in front of an instruction). They apply to a SINGLE delegated task (`{{ @agent ... }}`, the default agent of a plain `{{ }}`, what Ctrl+Enter hands over); a recipe step, `[[ @llm ]]`, `[[ $ ]]`, Ask AI and the Command Bar get none. The agent is its `agents.yaml` key (an alias such as `@cc` counts as the key `claude-code`); the file name is the key with every character other than `A-Z a-z 0-9 . _ -` turned into `_`. Only the last 64 KB of a file is read; a line is a rule only if it starts with `- `, is at most 300 characters and holds no `<!--` / `-->` (the trailing `<!-- date -->` is dropped); the newest 30 rules / 4,000 characters are used, older ones count as `skipped`. A definition that never passes `{instruction}` to its command (`append_instruction: false` and no `{instruction}` in `args`) cannot receive them. `lessons: false` goes inside the agent's own entry in `agents.yaml`, and an entry you write there replaces the built-in one of the same key, so for a built-in agent it must carry the whole definition (command and args) too, not the single line. The proposal step sends an excerpt of the failed run (instruction head 1,500 characters, output tail 4,000, error 800, the person's note 500, secrets blanked out) to the text model of Settings, only after the person presses Create a proposal; that is why no RPC method or command can start it. Not verified on a real Mac, with a screen reader, or with an IME in the note box.
- `hash` = first 16 hex chars of SHA-256 (UTF-8) of the LF text. `generation` is a process-wide counter of RPC writes only (`buffer save` does not count). A write's result has `previous_hash` and `hash`.
- MD-Memo's own LLM keys live only in `config.json` (not in `GEMINI_API_KEY`-style variables). Only `TYPESAFE_API_KEY`, `JEV_API_KEY`, `OPENROUTER_API_KEY` (CLI only), `JEV_MODEL`, `JEV_API_URL` and PATH-like variables are read (setup-guide.md (d)). Slot agents get keys from `<projectRoot>/.env`.
- Ctrl+Enter is the Auto selector: it decides for the ONE line or task under the caret (interfaces.md 4.1). A task notation (`[[ @llm ]]`, `[[ $ ]]`, `{{ @agent }}`) runs; a clear request for the built-in LLM is rewritten and runs at once; an agent or command request is only rewritten (a second press runs it, Ctrl+Z undoes it); anything unclear opens the Ask AI bar and changes nothing. The rules are fixed and can be wrong. The old rule (the caret's slot, else the next one, else the first in the note) holds only with `autoSelector.enabled` off, on a blank line, in a code fence, or with the caret in (or a line holding) a classic slot.
- A task's result goes BELOW its line in a `<!-- md-memo:res id -->` ... `<!-- /md-memo:res -->` block (the editor shows the comment lines, the preview hides them); a classic `{{ }}` still REPLACES the slot. No LLM configured: the toast "LLM is not configured (Settings -> AI Models)" and the note is untouched. `autoSelector` is a `config.json` key; `aliases` and `snippets` are `agents.yaml` keys the page reads at start.
- A `.mdmemopack` settings package is written and applied only by the running app (Settings -> Export... / Import...). Never "import" one by writing `config.json` or by unzipping it into `<cfg>` or a project; reading its `manifest.json` with a zip reader is fine (interfaces.md 5.2, setup-guide.md (h)).
- Capture features by platform: the Quick Capture popup, its hotkey `shortcuts.quickCapture` (default Ctrl+Shift+Q, empty = off), Screen Capture, on-device Whisper and the Send To entry are Windows only (Whisper: x64 only); on macOS the toolbar button and the shortcut row do not appear and Settings says Whisper is only available on Windows (x64) for now. The hot folder (off by default) and `md-memo ocr` run on both, but on macOS images are read by the cloud vision model only and audio by Gemini only. `vision.ocrMode` `"on-device"` ("Keep images on this PC") exists on Windows only. `voice.engine` applies to the hot folder and the Discord bridge, never to live voice input or Mobile Drop. `md-memo ocr` finds the scrap folder as the app does: top-level `scrap_dir` of `config.json`, overridden by `scraps.scrapDir`.
- In the editor every openable link is underlined and Ctrl/Cmd+Click opens files, folders and web addresses (Alt/Option+Click reveals only files); notes over 100,000 characters get no underline (Ctrl+Click still works) and notes over 120,000 characters keep plain 1..N line numbers (interfaces.md 3.3, 3.8). Verified in Chromium only, not yet on a real Mac.
- The built-in agent definitions changed after v1.8.0 (`claude -p`, `codex exec`, `agy` without `--dangerously-skip-permissions`; not run on the maintainer's machine); an agents file written earlier keeps its old copies, which Settings -> Agent lists (interfaces.md 3.1.3). Builds from 1.10.0 can switch an agent off (`enabled: false` / `disabled_agents`), tell the user before a run when the agent's program is not on PATH (`Agent "hermes" needs "ollama", which was not found in PATH ...`; only the program is checked, not models) and hand the agent the long form of the temp note's path on Windows (interfaces.md 3.1.5, 3.1). Check `--help` before relying on any flag. An agent with a permission-skipping flag, or a shell agent that would run the appended instruction as code, is confirmed by the user once before it runs.
- This folder doubles as an MD-Memo slot skill: `{{ @md-memo: ... }}` in a note inside this repository passes this file's body to the agent (an agent key or alias named `md-memo` would win, because `@name` is resolved agent first).
