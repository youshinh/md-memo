# MD-Memo troubleshooting (symptom -> cause -> fix)

Every cause below was traced in source (file named in "Source of truth"). `(unverified)` marks a step that rests on general OS or browser behaviour rather than this repository. Do not change files until you know the cause; back up before any edit (see `setup-guide.md` (a)). `<cfg>` = `%AppData%\md-memo\` (Windows) or `~/Library/Application Support/md-memo/` (macOS).

---

## 1. Command line and JSON-RPC

| Symptom | Cause | Fix |
|---|---|---|
| `Error: md-memo is not running. ...` (versions before 1.7.1 add `Launch md-memo first or use --headless.`) | `<cfg>/ipc-session.json` is missing, its PID is dead, or its port refuses a connection (the CLI deletes a stale file). The old `--headless` hint is wrong for `buffer`/`tab`/`ui`. | Ask the user to start MD-Memo normally. A tray-resident Windows instance is still running with its window hidden; then the file exists. Do not run bare `md-memo` yourself. |
| `failed to connect to running instance at 127.0.0.1:PORT` | The session file points at a port nothing listens on any more (crash between the liveness check and the call), or a local firewall driver blocks loopback. | Retry once; if it persists ask the user to restart MD-Memo. |
| `i/o timeout`, `context deadline exceeded`, `failed to get buffer: ...` | The CLI waits 3 s, the app 5 s; the WebView was busy or the page is not running (`webview is not running`). If the window is hidden in the tray try `md-memo ui activate` first (unverified whether hidden pages are slower). | Retry after `ui activate`; avoid long `ui eval` code. |
| `no active selection` (exit 1, RPC -32003) | Nothing is selected in the FOCUSED editor pane (start == end), or `--tab` names another tab (the tab is selected first and its selection is empty). | Ask the user to select text (or select it through the UI), then call again without `--tab` or with the active tab. |
| `conflict: expected hash X but buffer is at Y` (exit 1, -32001) | The buffer changed since you read it (any edit, including the user typing), or another RPC writer bumped `generation`. | `buffer get --json` again, redo the edit, retry with the new hash. Do not drop `--expected-hash` to "make it work". |
| `selection changed before replace could be applied` | The caret moved between the two internal round trips of `replace-selection`. | Re-read the selection and retry. |
| `--tab <id>` seems ignored by `buffer set/append/replace` | It is ignored: those RPCs always act on the primary pane's active tab (`app_rpc.go`). Only `buffer get`, `get --selection`, `replace-selection` honour it. | `tab switch <id>` (valid ids only), write, switch back. Tell the user, because switching changes what they see. |
| `buffer get --tab bogus` returns an empty buffer | Unknown ids are not errors (JS returns null, Go accepts it). | Take ids from `tab list`. |
| After `tab switch <bad id>` typing seems to go nowhere, tab bar shows no active tab | `selectTab` sets `activeTabId` before checking the tab exists (`app.js`), leaving no valid active tab. | Ask the user to click any tab. Prevent by using only ids from `tab list`. |
| `buffer set` emptied the note | No content argument and stdin was a pipe with no data (or a closed stdin) -> empty content. | Ctrl+Z in the editor restores it (writes are undoable). Always pass content explicitly. |
| My `buffer set` changed the file on disk | RPC writes fire the editor's `input` event: with `general.autoSave` true and a tab bound to a file, the file is saved ~1.5 s later. | Expected. Turn autosave off first only if the user agrees. |
| Non-ASCII text arrives garbled from PowerShell 5.1 | Windows PowerShell 5.1 encodes text piped to native programs in the legacy code page, and decodes what a native program prints the same way, so `md-memo buffer get \| Set-Content x.md` or `> x.md` also garbles Japanese (unverified, general PowerShell behaviour). | Reading a note into a file: `md-memo buffer get --out x.md` (the CLI writes UTF-8 itself; `interfaces.md` 1.2; `(unverified on a real PowerShell 5.1)`). Writing text into the note: use PowerShell 7, or call the JSON-RPC route with UTF-8 bytes. |
| `md-memo info` / `scrap` / `config` is treated as a file name, or opens the GUI | The build is older than these commands (1.8.0 and earlier do not have them), so the word is not a command. Never retry it: a bare unknown word can start the app. | Run `md-memo --version` and `md-memo --help` (they never start the GUI) and read the command list first. Without `config get`, do not read `config.json`; ask the user. |
| `Error: no such key: ...` from `md-memo config get` | The dotted path does not exist in `config.json` (a key that was never written also counts: defaults are not filled in). | `md-memo config get` for the whole redacted file, then pick a path from it. A secret shows as `<set>` / `<unset>`: that is the answer, the value is deliberately not available. |
| `Error: cannot use ...config.json: ...` from `md-memo config get` | `config.json` is unreadable or not valid JSON (a hand edit with a trailing comma, say). `info` and `ocr` fall back to the defaults silently, `config get` does not. | Ask the user to fix or restore the file (with MD-Memo closed); do not try to repair it yourself while the app runs. |
| `Error: invalid date ...` from `md-memo scrap` | A date must be `YYYY-MM-DD` with a two-digit month and day and a real day (`2026-9-5` and `2026-02-30` are refused). | Rewrite the date. |
| `md-memo scrap search` finds nothing in a file you can see | With `--from` / `--to` only files named `YYYY-MM-DD.md` are searched; a file in a folder starting with `.` is never searched; the query is a plain substring (no regular expressions) and case-insensitive. | Drop the range, or search a shorter text. `md-memo info` shows which folder is searched (`scrap_dir`). |
| `md-memo buffer get` prints nothing / returns immediately in PowerShell (also: `$LASTEXITCODE` is stale, output is not captured) | `md-memo.exe` is a GUI-subsystem executable; PowerShell does not wait for it and may not capture its console output or exit code (unverified). Output is preserved when stdout is piped or redirected (`console_windows.go`). | Run `md-memo-cli` instead (`md-memo-cli buffer get --text`): the console-subsystem twin that sits next to `md-memo.exe` in the Windows zip of the release that contains it (check that the file exists). Same commands, flags, output and exit codes, but PowerShell and cmd wait for it. It never starts the app; with no arguments, a file or piped text it forwards to the running app or answers `Error: md-memo is not running. Start md-memo.exe first.` (exit 1). Without it (older zips): pipe `md-memo buffer get --text \| Out-String`, or use a Bash tool, or `Start-Process -Wait -NoNewWindow -RedirectStandardOutput`. |
| `md-memo --help` / `md-memo help` / `md-memo --version` starts the app | Only in builds before 1.7.1: they were not intercepted, so unknown words and flags fell through to the normal start. | Use `md-memo --headless help` on such a build (the version is `AppVersion` in `app.go`). From 1.7.1 on they print and exit 0 without starting anything. |
| `md-memo ocr` fails: `usage: md-memo ocr <imagePath>`, `cannot read <path>`, `OCR failed: ...`, `failed to append to scrap: ...`, or prints `(no text recognized)` | Exit 1 with the first three or the fourth: no path (flags such as `--json` must come before it), a path that does not exist or cannot be read, no OCR engine could read the image (cloud model not set up and, on Windows, the on-device fallback failed too; macOS has only the cloud model), or the scrap folder cannot be written. `(no text recognized)` is exit 0: the image held no readable text, and nothing was written. The command reads the scrap folder (top-level `scrap_dir`, overridden by `scraps.scrapDir`, as the app does) and `vision` from `config.json` on every call, needs no running MD-Memo, and gives up after 60 s. | Check the path, fix `vision.*` (`setup-guide.md` (b)), and see the OCR row in section 4. |
| `jev verify` exit `2` | "warn": the guard cannot vouch for the command (pipe to an interpreter, run-time-built string) but it is not known to be destructive. | Read the command; do not treat 2 as safe. `--json` gives `rule` and `reason`. |
| `jev verify` blocks a harmless `for f in *.txt; do echo $f; done` | `strict` (default) rejects unquoted variable expansion (`unquoted-var`). | Quote the variable, or judge with `--mode reviewed` if a person will read it. |
| `jev verify` says `parse` / `parseFailed` for PowerShell | The guard parses bash; PowerShell syntax may fail to parse; strict and unattended treat that as a block. `reviewed` falls back to the regex lists only. | Do not present a parse failure as "unsafe" or "safe": it is "not analysed". |
| `md-memo jev verify -rf` -> flag error | Text starting with `-` is parsed as a flag. | `md-memo jev verify -- "-rf ..."` (flags such as `--mode` go before the `--`). |
| CLI JSON when I wanted text | stdout is not a terminal, so JSON is the default. | `--text`. |

## 2. Window, tray, hotkey, single instance

| Symptom | Cause | Fix |
|---|---|---|
| Launching MD-Memo again "does nothing" / the existing window appears | By design: one instance. Windows: named mutex `Local\MDMemo_SingleInstance_Mutex_v1` plus a broadcast message; macOS: `flock` on `<cfg>/instance.lock` plus an IPC `activate`. `md-memo <file>` opens the file in the running instance's new tab; `cmd \| md-memo` appends to today's scrap in it. | Nothing to fix. There is no way to open a second window/instance. |
| Closing the window leaves a process running (Windows) | `general.trayResident` defaults to true: WM_CLOSE hides to the tray. | Tray icon -> Quit, or set `general.trayResident` false (app closed) so close exits. Ctrl+W on the last tab exits regardless. |
| No tray icon on macOS | None exists by design; the close button hides the window (always); Cmd+Q quits; the Dock icon or the hotkey brings it back. `trayResident` has no effect there. | - |
| Global hotkey does nothing | Another program owns the combination (Windows `RegisterHotKey` fails silently at start), or the configured string cannot be parsed (Windows: a non-letter/digit/F-key/Space/Enter/Esc key such as ArrowUp). The hotkey only brings the window forward; it never hides it. | Change it in Settings -> Shortcuts (a refused registration reverts the value and shows a toast), or edit `shortcuts.globalSummon` with the app closed. |
| Quick Capture (Windows): `Ctrl+Shift+Q` does nothing, or Settings refuses a new combination with the toast "This shortcut could not be registered with the system. Try another combination." | Another program already owns the combination, so `RegisterHotKey` fails: silently at start-up, and in Settings the change is refused and the previous key comes back. Or `shortcuts.quickCapture` is `""` (no hotkey, by design), or the string cannot be parsed. macOS has no Quick Capture at all: no toolbar button, no palette entry, no shortcut row. | Choose another combination in Settings -> Shortcuts ("Quick Capture (global, opens the note popup)"), or clear it and open the popup from the toolbar button, the tray item "Quick Capture" or the palette. With the app closed, `shortcuts.quickCapture` may be edited (a missing key = the default `Ctrl+Shift+Q`, `""` = off). |
| Quick Capture popup vanishes by itself, or AI Send did not correct the text | The popup closes 1 second after it loses focus (it stays when focus comes back in time). AI Send saves the text exactly as typed when `general.aiCorrection` is false, `text.baseUrl` is empty, the model fails or answers nothing, or 30 s pass; closing the popup while it waits does not lose the note. | Click back into the popup within a second; set the text model in Settings -> AI Models; use Send when no correction is wanted. |
| Screen Capture (Windows): a window cannot be picked, the capture is black, or nothing was saved | Only visible top-level windows can be picked: not minimized, not on another virtual desktop, not the desktop background, not under 24 px, not click-through overlays. A covered or partly off-screen window is captured from the window itself; every other window and every dragged rectangle is read from the screen, and video players or protected content can come out black. Esc or a right-click cancels and saves nothing; the picker gives up by itself after 2 minutes. macOS has no Screen Capture. | Drag a rectangle instead of clicking, bring the window to the front, and try again. |
| Port 41739 is busy | MD-Memo silently binds a random port for its embedded UI. Browser storage is per origin (host AND port), so the cached config copy, session copy, CLI history, last Command Bar mode, voice-rescue map, workspace folder and font size from earlier runs are not visible (unverified web-platform rule). `config.json` and `session.json` are still read from disk. Symptoms: voice rescue links say the cache is missing although `<cfg>/voice_cache` holds the file; the workspace folder is forgotten. | Free the port and restart MD-Memo (find the owner with `netstat -ano \| findstr 41739` on Windows or `lsof -i :41739` on macOS, unverified commands of the OS). |
| Port 49152 is busy | The IPC server takes a random port and writes it to `ipc-session.json`. | Always read the port from that file (the CLI does). |
| Windows: nothing starts / no window | The Microsoft Edge WebView2 Runtime is missing (`Failed to initialize WebView2`, only visible when started from a console). | Install the runtime. |
| macOS: "damaged", "unidentified developer" or "Apple could not verify ... free of malware" | Releases are ad-hoc signed, not notarized. | macOS 15+: click Done (not Move to Trash), then System Settings -> Privacy & Security -> Security -> Open Anyway (shown for about an hour after the attempt) and enter the login password. macOS 14 and earlier: right-click -> Open. Any version: `xattr -dr com.apple.quarantine "MD-Memo.app"`. |
| macOS: agent CLIs, `git`, `jq`, `cloudflared` "not found" right after launch | A GUI-launched app gets launchd's tiny PATH. `pkg/shellenv` repairs PATH in a background goroutine after start (login shell probe, 3 s per attempt, static fallback list) and then clears the 30 s "is it installed" cache. | Wait a few seconds and retry; if a tool lives outside the login shell's PATH, launch MD-Memo from a terminal that has it, or use absolute paths in `agents.yaml`. |
| Windows: a CLI I just installed is "not found" | The process keeps the PATH it started with (`exec.LookPath` reads the process environment; general Windows behaviour). | Fully quit MD-Memo (tray -> Quit) and start it again. `cloudflared` is the exception: fallback install folders are searched at click time. |

## 3. Settings and files

| Symptom | Cause | Fix |
|---|---|---|
| My edit of `config.json` has no effect | Any of: (1) MD-Memo was running: the frontend read the file once at start; (2) invalid JSON: `JSON.parse` failure is swallowed (`console.warn`) and Go's parsers fall back to defaults, so the WHOLE file is ignored silently; (3) a BOM; (4) you deleted a key and the browser-storage copy re-supplied the old value; (5) you edited only top-level `scrap_dir` while nested `scraps.scrapDir` exists (Go: nested wins; frontend: nested first) or the reverse when `scraps` is absent; (6) an unknown top-level key (dropped at the next UI save); (7) a slot key while `agents.yaml` exists (see below). | Quit MD-Memo, validate the JSON, write explicit values, keep nested and mirrored keys equal, restart. |
| My edit was overwritten | The app rewrote `config.json` from memory: Settings Save, or a click on the `Predict`, `Autosave`, `IME`, `Action` badges, or Ollama setup finishing. | Edit only while closed. |
| A shortcut I typed into `config.json` does not work | Not validated: reserved combos (Ctrl+Tab, Ctrl+Comma, Ctrl+Shift+V, Ctrl+Alt+V, Alt+T, Ctrl+Right, every Ctrl+Enter variant, clipboard/undo keys) are shadowed by fixed handlers; a duplicate is not resolved (the first match in handler order wins); on macOS reserved combos are reset to the default at load; every Ctrl+Enter variant inside the editor is taken first by the Auto selector (`interfaces.md` 4.1), so it can never be another action's key. | Pick another combination; use the Settings recorder for conflict handling. |
| The Settings "Agent timeout" seems ignored | With an external `agents.yaml` present the Go runner takes `timeout_seconds` from that file only (default 180); the UI value is used only when no agents file exists. "Open agents.yaml" creates one. | Edit `timeout_seconds` in the agents file. |
| `agents.yaml` edit ignored / my custom agent missing | (1) YAML/JSON syntax error: the file is silently skipped and built-in defaults are used; (2) an earlier candidate exists and shadows yours (`<scrapDir>/.md-memo/agents.*` beats `<cfg>/agents.*`; a broken first file does not fall through); (3) notations, `aliases` or `snippets` changed but the frontend copy is stale until restart (the Go side sees a change at the next run); (4) `slot_profiles`/`recipes` REPLACE the built-ins (your list must contain everything you want). | Lint the file, check `<scrapDir>/.md-memo/`, restart after changing notations. |
| Hover Peek never shows text | `hover_peek_enabled` omitted from `agents.yaml` reads as `false` (Go zero value). | Add `hover_peek_enabled: true`. |
| "Max Pipe Input Size" does nothing | The value is stored but no code reads it; the limit is the constant 10 MB (`main.go`). | Nothing to fix; do not promise it. |
| `jev.json` has no effect | Not implemented: no loader exists. | Do not create it. |
| Settings Save stopped my Ollama | Saving after moving both text and ghost-text URLs away from `11434` calls `stopOllamaService` (Windows `taskkill /F /IM ollama.exe /T` and `"ollama app.exe"`; Unix `pkill -f 'ollama serve'`), which kills every Ollama process. | Warn the user before changing those URLs in the UI; a file edit while closed does not trigger it. |
| Toolbar icon / context-menu item disappeared | `general.toolbarLayout.hidden` / `contextMenuLayout.hidden` lists its element id. | Settings -> General -> Toolbar and right-click menu -> reset, or remove the id (app closed). The Settings icon cannot be hidden. |
| Settings -> Import... fails, or an item is skipped | The app refused the file or the item. Failure messages are bilingual (Japanese, then English): `not a zip file` / `not a settings package or a settings JSON file` (wrong file), `unsafe path in package` (a `..`, absolute or drive path, a backslash or a Windows reserved name inside), `size limit exceeded` / `too many entries` (limits in `interfaces.md` 5.2), `package is from a newer version; update the app`, `invalid manifest` / `invalid entry in package` / `duplicate entry names`. In the dialog, the badge "needs a project" (row disabled) means no project folder was found; an agents file that is empty or does not parse is skipped with the reason (`does not parse: ...`) and shown under "Skipped ..." in the result panel. | Use a package that MD-Memo's own Export... wrote; update MD-Memo for a newer package. For "needs a project": save the note to a file, or open a folder (Ctrl+Shift+O), inside the project, then import again. Fix the YAML and export again. Do not work around a refusal by unzipping the package or writing `config.json`. |
| The settings did not change after an import | Only the ticked sections are applied (Sync is unticked by default; "None of the selected settings were found in the file." when the package lacks them). An empty API key in a package never erases a key that is already set. Some settings take effect only after a restart ("Some settings take effect after you restart MD-Memo."). The Settings dialog re-opens after the settings were applied and shows the merged values. Agents files apply at the next agent run (a changed notation may need a restart, `setup-guide.md` (a) step 4). | Read the result panel, restart MD-Memo when it asks, tick the missing section and import again. Never edit `config.json` to force a result. |

## 4. AI features

| Symptom | Cause | Fix |
|---|---|---|
| Quick Actions (Ctrl+J) does nothing | Check in order: the status-bar badge reads `Action: OFF` (`action.enabled` false; Ctrl+J is disabled then); focus is not inside a note textarea (the trigger requires `document.activeElement` to be an editor, so the Find bar, tab bar or a dialog blocks it); `shortcuts.quickActions` changed or empty; an IME composition is active (suppressed); in Manual mode only Ctrl+J opens it (auto popup off). | Click the badge to cycle On -> Manual -> Off, click into the note, check the shortcut in Settings -> Shortcuts. |
| Quick Actions never seems to use Jev (the cards are always the built-in ones) | Jev only CHOOSES among the built-in candidates; it never writes new cards, so every card comes from the same fixed set and Jev decides which of them are shown. If the choice never differs from the keyword rules', the built-in rules are answering: `action.apiKey` is empty; a TypeSafe key sits next to the default OpenRouter Base URL (it is sent nowhere; TypeSafe needs `https://api.typesafe.ai`); the key is OpenRouter's but `action.model` is not a Jev name (that means chat completions); the key or credit is refused (401/402), the service answered 422/429/5xx, or 5 s passed; Jev's answer was too uncertain (Choice confidence < 0.15); or the note excerpt is empty. A failure never tries the key on another engine. | Settings -> Agent -> Suggestions: OpenRouter key -> keep Base URL `https://openrouter.ai/api/v1` and model `jev-latest`; TypeSafe key -> Base URL `https://api.typesafe.ai`. A candidate that is missing altogether was never in the built-in pool. |
| Quick Actions opens but a card fails or shows the wrong folder | `sh` cards run in MD-Memo's own working directory (no `Dir` is set), so `git status -s` reports on whatever folder MD-Memo was started from, and the strict guard refuses unquoted variables, `rm`, `sudo`-wrapped destructive commands and more. Windows runs them through `powershell -NoProfile -NonInteractive -Command`; timeout 20 s. | Use a card whose command does not depend on the folder, or run the command in a terminal. |
| A `write`-kind Quick Actions card fails with a connection error | Derived from code, not run: a `doc` card whose command is not a slot goes to the generative branch, whose LLM handler reads an `llm` object (or top-level `baseUrl`/`model`/`apiKey`) from `config.json` (`app_jev.go`), while the UI stores its LLM under `text`; with neither present the request has an empty base URL. Local rules only produce slot-style `doc` cards, so this needs a remote engine. | Report as a bug; do not paper over it with an `llm` key (the next UI save drops unknown top-level keys). |
| Ctrl+Enter ran a slot elsewhere in the note (or on a slot I did not mean) | That is the CLASSIC rule, which now applies only when the Auto selector hands over to it: `autoSelector.enabled` is off, the line (or selection) is blank, the caret is inside a code fence or inside a classic slot, or the line already contains a classic slot notation. It picks the slot under the caret, else the NEAREST slot after the caret, else the FIRST slot in the note; "No slot found" appears only when the note has none. | Move the caret into the intended slot. With the Auto selector on, a non-blank line outside code that holds no slot is judged by the rules in the next row instead. Esc within the Ghost Diff window reverts. |
| Ctrl+Enter does not do what I expected (rewrote the line, opened the ask bar, ran something else, or nothing) | One key now decides for the ONE line or task under the caret; the first match wins (`interfaces.md` 4.1): a caret inside a result block gives a toast and nothing else; a task notation under the caret (`[[ @llm ]]`, `[[ $ ]]`, `{{ @agent }}`) runs that one task, even with the setting off; a classic slot at the caret, the setting off, a blank line or a code fence use the classic rule (row above); a partial-line or multi-line selection, or a line that is not clearly a request, opens the ask bar; a clear request for the LLM becomes `[[ @llm ... ]]` and runs AT ONCE, one for an agent or a command is only rewritten. The judgement is by fixed rules, not a model, and can be wrong (a polite note such as 「資料は事前に共有してください」 counts as an LLM request). An Enter that confirms an IME conversion, and a held key, do nothing. | Write the notation yourself so nothing is guessed. Ctrl+Z undoes a rewrite (one step). To get the old behaviour everywhere, untick Settings -> Agent -> "Let Ctrl+Enter decide..." (`autoSelector.enabled`). Cancel a live run in the task panel (Alt+T). |
| Ctrl+Enter only rewrote my line to `{{ @agent ... }}` or `[[ $ ... ]]` and nothing ran | By design while `autoSelector.agentConfirm` is on (the default): an agent or command request stops after the rewrite with the toast "Rewritten as an agent task. Ctrl+Enter runs it, Ctrl+Z undoes." (or "Rewritten as a command. ..."). Only the LLM branch runs at once. | Press Ctrl+Enter again on the rewritten line, or Ctrl+Z to undo, or untick "Confirm before an auto-detected agent or command runs" to make it run at once. |
| Ctrl+Enter opened the ask bar instead of running my line | The line was not judged a clear request (a plain sentence, an unclear question, a heading, a URL, code, over 240 characters), or the selection is part of a line or several lines, or the line looks like a command that writes or destroys (`rm`, `del`, `mv`, `sudo`, a redirect `>` ...), which is never turned into a command automatically. Opening the bar changes nothing in the note. With no LLM configured the bar does not open and a toast says so (row on "LLM is not configured"). | Type what the AI should do and press Enter: it is saved as `[[ @llm ... ]]` on a new line below the text and runs. To run a command write `[[ $ ... ]]` yourself; the safety guard still checks it. |
| Toast `Agent "<name>" not found (check agents.yaml and PATH). Rewritten anyway; Ctrl+Z undoes.` (it follows "Rewritten as an agent task.") | The rewrite happened anyway; `<name>` is the `agents` key the line was rewritten to (the agent named by `@name`, else `default_agent`; if that names no agent the first defined one). Either the agent is not defined (a typo, or an alias added to agents.yaml after MD-Memo started, which the page does not know until restart), or its `command` is not on the PATH of the GUI process (`CheckAgentAvailability`; PATH lookups are cached 30 s; agents run without a shell). If you press Ctrl+Enter again anyway, the block shows the runner's error (`エージェント起動失敗: ...`). | Ctrl+Z undoes the rewrite. Fix the name or alias in agents.yaml and restart, set `default_agent`, or install the CLI / fix PATH (section 2); then press Ctrl+Enter again. |
| `{{ ⟳ 実行中... }}` stays after a restart | The placeholder is ordinary note text; the run died with the app. The parser skips placeholders, so it will not re-run. | Replace it with the original instruction (Ctrl+Z may work within the session). |
| Slot says `[U+26A0] エラー: エージェント起動失敗: ... (再試行: Ctrl+Enter)` (`[U+26A0]` = the warning-sign character the app writes; match on `エラー:`) | `exec` could not start the command: not on the GUI process's PATH, or the executable name is wrong. Agents run without a shell, so shell built-ins, aliases and `~` do not work. | Install the CLI, fix PATH (see section 2), or give an absolute path in `command`. Retry with Ctrl+Enter in the same slot. |
| Slot says `[U+26A0] エラー: <stderr text>` | The agent exited non-zero; the first 1000 characters of stderr are shown. Wrong flags are the usual cause: the built-in `codex` entry up to v1.8.0 used `--execute --file` and `claude-code` used `--file {file} --prompt {instruction}`, neither of which those CLIs accept; an agents file written from the old template still holds them (Settings -> Agent lists them under "Agent definitions to review"). With the new `agy` entry (no `--dangerously-skip-permissions`) agy may also stop because print mode cannot ask for a permission. | Run the command by hand with the same arguments; fix `args` (the "Copy the new definition" button gives today's entry). For agy, add the flag back only if the user wants agy to act without asking; MD-Memo then asks once before it runs. For codex outside a Git repository, `codex exec --help` lists `--skip-git-repo-check` (not tried by MD-Memo's maintainer). |
| A dialog "The agent "<key>" is set up to act without asking you first" appears on Ctrl+Enter | The agent's definition has a permission-skipping flag (`--dangerously-skip-permissions`, `--allow-dangerously-skip-permissions`, `--dangerously-bypass-approvals-and-sandbox`, `--yolo`, `--full-auto`, `--auto-approve`) or is a shell that would run the instruction as code (`interfaces.md` 3.1.3). | Run starts it and is remembered (`config.json` `agentAck`) until the command line changes; Cancel leaves the note untouched. To stop being asked for good, remove the flag from `args` (or set `append_instruction: false` for a shell). |
| Status bar "N agent definition(s) need a look", or the Settings box "Agent definitions to review" | The agents file (or `config.json` `agents`) holds a copy of a built-in definition MD-Memo has replaced, or a shell agent that would run the instruction as code.
